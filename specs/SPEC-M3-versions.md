2026-09-28 立。擁有者在 `handoff/HANDOFF-2026-09-28h-locks-land.md` 的三個選項之後說「展開後續工作」；A（版本）是

## 1. 為什麼要有

路線圖 §5.5 的完成判準有一格「版本正確」，一直沒量。交接留下兩個問題：我們的條件式存檔之後，Nextcloud 自己的
檔案版本長什麼樣；以及頁面持有鎖的時候，有人從 Files 還原舊版本會怎樣——還原也是一次寫入，會被 423 擋下，
還是像 finding 102 那樣寫穿。

## 2. 第 0 步量到的事實（已觀察）

`findings/evidence/m3-versions/README.md`，HTTP 層，V1–V6 兩輪一致、V7 三輪。決定這一步怎麼做的幾條：

- **我們的存檔在版本上跟一般用戶端沒有差別**：token 鎖＋條件式 PUT 與無鎖無條件 PUT，同樣的時間間隔，歷史形狀相同
  （上傳時的內容、第一次存檔的內容，外加一格「目前」）。版本作者都是 `admin`。
- **上鎖、解鎖會換 ETag，但不改 mtime、不產生版本。**
- 版本清單裡有一格代表「目前的內容」（revision＝檔案 mtime，GET 它是 404），其餘才是舊版本。
- **同一秒內存兩次，第一次不會留在歷史裡**（版本檔以 mtime 的秒數命名）。無鎖的一般用戶端一樣，是 Nextcloud 的行為。
- **還原會穿過我們的 token 鎖**：持有者自己在另一個分頁還原（Files 版本分頁送的就是這個請求，不帶 token——讀自出貨的
  source map，沒在瀏覽器裡看過）是 201，有寫入權的收件人還原也是 201；鎖還在、token 不變；ETag 換了、mtime 回到被還原的
  那個版本的時間；還原前的內容被存成一個版本——~~。~~**除非最後兩次寫入落在同一秒**：那時還原前的內容哪裡都不留
  （finding 104，同秒 5/5、跨秒 5/5 保住）。原因（讀原始碼）：files_lock 的儲存層包裝只擋使用者鎖與 app 鎖，不看 token 鎖；token 鎖只由 DAV
  `files/` 路徑上的 Sabre 外掛執行，而版本的端點不在那條路上。
- **對照組**：收件人持有**使用者鎖**時，擁有者的還原被擋（500 `ManuallyLockedException`，檔案不變）。所以差別在鎖的種類，
  不在「還原從不檢查鎖」。~~（兩輪）~~ 前兩輪還原的是 V4 已還原過的那一格＝把目前的位元組還原到自己身上，「檔案不變」
  不算證據；改成還原一格內容不同的舊版本之後再兩輪，同樣 500、檔案仍是原本的內容（審核第 3 項）。被拒絕的還原會留下一個
  多餘的 `.v<目前 mtime>` 檔（目前那格的 GET 從 404 變 200）。
- 還原之後宿主的下一次存檔（舊 `If-Match`＋token）是 **412**，什麼都沒寫、也沒多出版本。宿主在這個情況走的分支是
  鎖與權限規格的 S3（token 還在＝不重送、直接另存衝突副本），由 K12 驅動、已計數。
- **finding 103**：同一秒內別人的寫入不會換 ETag（23/23），所以帶舊 ETag 的 `If-Match` PUT 會蓋掉它（204）。
  跨秒就是 412（13/13）。被蓋掉的內容仍在版本歷史裡。

## 3. 宿主的行為：不改

`litecore` 宿主（`49cc4ab`）、產品頁（`fbfb59a4…`）、殼層（v53）、引擎都不動。理由：

- 版本是 Nextcloud 在每一次寫入時自己留的；宿主的寫入在這件事上跟一般用戶端一樣（第 2 節）。
- 還原穿過鎖之後，宿主的下一次存檔已經由 S3 接住：不覆寫、另存衝突副本、鎖留著。沒有資料遺失路徑要補。
- 103 在宿主這一側關不掉（第 5 節）。

## 5. 明確不承諾

- **頁面開著時的還原不會出現在頁面上。**頁面繼續顯示還原前的內容；下一次存檔另存衝突副本，原檔留著還原的結果。
  頁面沒有「重新載入伺服器版本」的功能。
- **同一秒內的寫入 `If-Match` 分不出來（finding 103）。**宿主持有鎖時，照規矩來的用戶端本來就寫不進來，窗口只對繞過鎖的
  寫入開著（拿到 token 的人，finding 102；不看 token 鎖的伺服器端寫入）。還原通常不在此列：它把 mtime 設回被還原那一格的時間，那個時間比目前早，實測 ETag 都換了（V3、V4）。例外（推論，未量）：同一秒存兩次之後，清單裡 revision 等於目前 mtime 的那一格裝的是第一次的內容；用 DAV 還原**那一格**，mtime 不變，依 103 的機制 ETag 也不會換。Files 把那一格當成「目前的版本」顯示。
  宿主**沒有**持有鎖時（上鎖失敗、鎖過期；鎖被解掉不算——解鎖會另寫新 ETag），任何人的寫入若與宿主手上那個 ETag 所屬的
  寫入落在同一秒，宿主的下一次存檔會蓋掉它；被蓋掉的內容留在版本歷史裡，直到有人還原（104）或保留政策清掉它。
  宿主這一側能縮小窗口（例如存檔前比對內容）；~~關不掉~~ 能不能關掉沒有研究；**不做**，除非擁有者要。
- **同一秒內的兩次寫入之後，任何還原都會讓較晚那次永久遺失（finding 104）。**宿主自己一秒內存兩次（按得夠快就會）就滿足
