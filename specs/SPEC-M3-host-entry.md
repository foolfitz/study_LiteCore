# SPEC M3：產品頁的宿主入口

2026-09-28 立。擁有者裁示 A（`handoff/HANDOFF-2026-09-28e-m3-skeleton-opens-save-needs-a-host-entry.md`）：
在產品頁加一個宿主入口，趁 soak 還是 0/12、沒有已押的執行會作廢。

## 1. 為什麼要有

M3 骨架（`findings/evidence/m3-skeleton/RESULT.md`）證明 Files → E1h 路由 → WebDAV 取檔 → 出貨編輯器
開得起來，但借道產品自己的 `#file` 輸入框。**已觀察**的兩個代價：

- 產品先開自帶範例，約占開檔時間一半（48–62%，看用哪個時鐘）；
- 存回做不到：`saveDocument()` 把位元組交給下載連結，宿主拿不到。

路線圖 §5.4 的寫回、鎖、版本、衝突全卡在第二點。

## 2. 契約

宿主在**匯入頁面模組之前**放好一個物件：

```js
globalThis.liteCoreHost = {
  load: async () => ({ bytes /* ArrayBuffer */, name /* string */ }),
  save: async (bytes /* ArrayBuffer */, { name }) => { /* 失敗就 throw */ },
};
```

頁面在模組求值時讀它**一次**（之後才出現的不算宿主）。有宿主時：

1. **不開自帶範例**、不抓 `e1-fixtures/manifest.json`；向 `load()` 要文件，照使用者自己開檔的同一條路
   （`openDocument(bytes, name)`）開啟。
2. **關掉本機的兩個開檔入口**（範例選單、開啟檔案）。理由：從本機開了別的文件，下一次儲存就會把它
   寫到宿主的檔案上。
3. **儲存**（按鈕與 Ctrl+S）先照舊 `session.save()` 取位元組，再交給 `save(bytes, { name })`，**不下載**。
   `save` throw 就顯示失敗（`存回 失敗`＋錯誤訊息），不假裝成功。有宿主時，**一次只跑一個存檔，從取位元組
   到宿主寫完**：連按兩次（或按住 Ctrl+S）否則會送出兩個都帶著開檔時版本的寫入，第二個被當成衝突，較新的
   內容反而沒寫進去；只排隊宿主那一半也不夠，因為兩個 `run("儲存")` 回來的順序取決於重畫。
4. `liteCoreHost` 存在但不是這個形狀（缺 `load` 或 `save`）：**拒絕開機**並說明，不退回範例——退回的話，
   使用者會以為自己在改宿主的檔案。

沒有宿主時，頁面行為**逐位元組以外完全不變**：這是第 4 節 H4 要量的。

**明確不承諾**：鎖、版本、衝突的判定都是**宿主**的事（頁面只負責把 throw 顯示出來）；dirty 追蹤與
離頁提醒不在這一版；公開分享連結不在範圍內。

**Nextcloud 宿主的做法**（`litecore` app 的 `js/litecore-editor.js`，不是頁面契約的一部分）：開檔記下版本
（`OC-ETag`，沒有就 `ETag`；兩者都沒有就拒絕開檔）；存回一律帶 `If-Match`，**絕不做無條件寫入**；成功就換成
新版本，下一次存回接著用。412（別處改過或移走）時不覆寫，把這次的位元組用 `If-None-Match: *` 另存成同資料夾
的「〈原名〉（衝突副本 〈時間〉）.odt」，並把這件事告訴頁面。

**2026-09-28 補（finding 103，不動判準）**：「別處改過」只在那次修改與宿主手上 ETag 所屬的寫入**不在同一秒**時看得到。Nextcloud 對同一秒內的第二次寫入不換 ETag，`If-Match` 會通過，宿主的存回會蓋掉它（被蓋掉的內容留在版本歷史裡）。H3 量到的是跨秒的情況；「絕不做無條件寫入」仍然成立，但不等於「不會蓋掉別人」。

**已知限制（讀原始碼得知，未另外量）**：`session.save()` 一完成就把 session 標成乾淨、並把這份位元組設為
回復依據（`editor-shell/editor-session.js` `save()` 的 finalize），這發生在宿主接受**之前**。所以宿主存回
失敗時，頁面上的文件看起來是乾淨的、伺服器卻沒有這份內容；下載模式本來就是同樣的語意。要讓「乾淨」等於
「宿主已收下」得改殼層，不在這一版。~~使用者的內容不會掉（回復依據就是最新內容），再按一次儲存就會重送~~
——**對衝突不成立**（審核 #6）：宿主不會自己更新版本，重送永遠是 412，宿主模式又沒有下載。所以衝突時由宿主
另存副本（上一段）。**仍會卡住的**：伺服器拒絕寫入但不是衝突（403 唯讀、423 鎖住、斷線），內容只在頁面裡、
沒有出口——已命名的限制，留給鎖與權限那一步。

## 4. 驗收判準（先於改動與任何量測寫下）

宿主＝`litecore` app（`~/Projects/Nextcloud_Apps/litecore`），環境同 M3 骨架。每瀏覽器 3 輪、每輪新瀏覽器。

- **H1 不開範例**：Files 點檔 → 編輯路由，產品 `ready`、文件名＝上傳的檔名；Chrome 的 CDP 裡**沒有**任何
  `e1-fixtures/` 請求；頁面上範例選單與開啟檔案按鈕 `disabled`。
- **H2 存回**：定位游標、`set-paragraph-heading`、按儲存 → 頁面顯示存回成功；**伺服器上的檔案**（runner 用
  WebDAV 取回）sha256 改變，且其 `content.xml` ~~含 `<text:h`~~ 有一個 Heading 1 段落（`<text:h>`，或樣式
  直接或經自動樣式的父樣式是 `Heading_20_1`；原檔沒有，runner 先檢查）；ETag 改變。**再插入一個標記文字、
  用 Ctrl+S 存第二次**：兩次都 204、第二次的 `If-Match` 等於第一次拿到的版本、伺服器位元組等於第二次送出的
  位元組；伺服器文件的段落文字拿掉標記後逐段等於原檔（防「名字對、內容是別份文件」）；沒有產生衝突副本。
- **H3 衝突不覆寫、內容不掉**：開檔後、按儲存前，runner 從伺服器端改寫檔案（另一份位元組）；按儲存 → 頁面顯示
  存回失敗（CONFLICT）；**等 5 秒**，頁面仍是同一份文件、同一個 revision、`ready`（沒有被重載蓋掉）；**再按一次**
  → 仍是 412、仍顯示失敗；伺服器上的檔案仍是 runner 寫的那一份（逐位元組）；兩份衝突副本的位元組等於兩次送出的
  位元組。
- **H4 沒有宿主時不變**：產品路徑回歸網（`run_e2_c_product_path.py`，v8）逐格結果與改動前相同；
  `make test-e2-c-static` exit 0。
- **H5 壞宿主拒絕**：`liteCoreHost = {}`（沒有 `load`）與「有 `load` 沒有 `save`」兩種 → 產品不 `ready`、
  不開範例（Chrome 無 `e1-fixtures/` 請求，且同一段 CDP 紀錄裡看得到編輯頁本身＝正向對照）、本機開檔入口
  `disabled`、畫面有說明。**只在 Chrome 量**：要在任何頁面腳本之前把 `liteCoreHost` 換掉，靠的是 CDP
  `Page.addScriptToEvaluateOnNewDocument`，這裡的 Firefox 驅動（WebDriver classic）沒有對應的東西。

H1–H3、H5 由 ~~`check_m3_skeleton_open.py` 的新臂~~ `wasm_sdk_probe/tools/check_m3_host_entry.py` 量（骨架那支
和它的證據綁在一起，不改），**先讓評分紅一次**（每條至少一個突變）。計數執行時，送出的殼層必須是已凍結的
generation（runner 拒絕否則）。H4 的基線＝`findings/evidence/098/product-path/v52-*.json`。
H1–H3 各 3/3 兩個瀏覽器（H1 在 open-save 與 conflict 兩臂的每一輪都判）、H4 全過、H5 Chrome 1/1，才算落地。

**如果這件事永遠沒做**：M3 停在「開得起來、存不回去」，§5.4 四件事都不能開始。
