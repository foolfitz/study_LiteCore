# Calc 多格格式與自動儲存：來源完成，等待後繼引擎建置

擁有者已確認上一批直接輸入、F2 與矩形選取的人工測試通過。本批接續多格 B／I／U 與自動儲存；已安裝的宿主仍是 **0.2.36／2b17a0e790b24eb3**，這份來源尚未部署。

## 多格格式的實作

新增 `ods-editor-v2` 後繼介面，在既有 cell ABI 後追加範圍讀取與粗體、斜體、底線操作，以 capability 隔開舊 v1。寫入明確指定工作表、地址矩形與 revision；不從引擎目前游標猜目標，不逐格發送寫入。三個字族的粗體／斜體項目交給同一次原生 `XMultiPropertySet`，事前檢查整個範圍，事後核對結果。寫入後失去確認則標示不確定、保留文件並拒絕後續修改，不宣稱當機後可回滾。

單次上限 **65,536 個邏輯儲存格**，空白格及隱藏列欄也計入。範圍可以包含完整合併格；若跨過合併格邊界，整筆拒絕，不擴大寫入。受保護工作表只有整段保護屬性一致且全部解鎖才允許；屬性混合時保守拒絕，包括可能全為 unlocked、但其他保護旗標不同的情形。混合格式顯示 `aria-pressed="mixed"`，按一次統一開啟，全部開啟後再按則關閉。格式後重新讀兩端幾何，保留選區與 active anchor。

以上是**已實作、尚未經原生編譯與 v2 執行驗證**的契約。已準備 native 22 案與雙瀏覽器每輪 40 案的工具；沒有執行結果就不列完成，也不切換出貨引擎。

## 自動儲存的實作

只有接上宿主的頁面啟用，使用與 Writer 相同的 **閒置 30 秒／未存滿五分鐘後至少停頓三秒／頁面隱藏時合條件立即嘗試**。只存已確認的模型變更，編輯中顯示「確認後自動儲存」；不強制提交草稿或 IME。選格、拖曳、暫存輸入、操作／存檔在途、未處理錯誤與不確定狀態都延後。

自動匯出保留編輯狀態；匯出或宿主寫入期間新收到的文字仍是未存草稿。發生副本、擱淺或其他儲存失敗後，停止自動重試，持續顯示暫停提醒；明確手動存回原檔成功才恢復。宿主已換到副本的工作階段繼續沿用既有副本目標，但維持自動儲存暫停。沒有宿主時不自動下載；離頁仍使用既有未存提醒，不承諾關頁時能完成非同步存檔。

自動儲存證據及審核處置集中在 [證據目錄](../findings/evidence/calc-range-autosave/README.md)。該瀏覽器工具使用真實頁面、凍結 v1 引擎與 ODS 匯出，但宿主是可控制的替身；不能拿它宣稱實際 WebDAV、鎖或 Files 已完成本批驗收。

正式 `auto-final-05` 的 Chrome／Firefox 各三輪共 **108／108**，十八份 ODS 由獨立 XML 核對；reader 的六個紅控制全拒絕。session／SDK／worker／host／autosave 單元 **45／45**；另有 autosave 七個、range 六個突變控制。Astra 讀取產物後確認此鏡像層可封閉。原生／v2 與實際 Files 尚未成立，不能用這份通過替代。

## 裁決、限制與下一步

Astra `/root/astra_calc_scope` 依擁有者授權裁決有限範圍，並逐項覆核 Claude Code 的審核意見；[裁決原文](../handoff/RULING-2026-10-25-calc-range-autosave.md)與完整審核紀錄均保留。原生範圍寫入參考本機 LibreOffice／Collabora 的 `ScCellRangesBase::setPropertyValues` 與 `ApplyAttributesOperation`；只是讀來源，未移植整套互動，也沒有啟動 Collabora 量測。

一般 cell commit 等待期間的連續按鍵接收，仍是未建立的後續限制。另在 `auto-final-03` 的 Firefox 第三輪開始前出現位址定位失敗：維持 A1、revision 0、無 session error，零個 autosave case。等公開 `ready` Promise 之後，`auto-final-04` 的 Chrome 仍出現同症狀，因此撤回單靠等待不足的歸因。固定紅案再直接證明 render 會把聚焦中的 B2 覆寫成 A1，已修成保留焦點內輸入、blur 才正規化，並將固定案例納入新的完整六輪；不宣稱這個機制解釋每一次歷史失敗，也不拼湊先前通過輪數。實際 OS 輸入法仍未由本批證明。

目前必要的人工步驟是依 [建置手冊](../handoff/RUNBOOK-build-calc-range-v2.md)執行小橋接與 SDK 後繼連結，預估 3–10 分鐘，不是重建 LibreOffice core。這條界線來自擁有者的 AGENTS.md：會編譯的 make 預設由擁有者執行。建置完成後由 agent 繼續原生／v2 瀏覽器、合併候選的 Files 實測、封存、打包與受保護安裝；不需要重做前批已通過的人工測試。完整 K、全域 pins、BINDING 與計數仍延後。
