什麼會讓重用的引擎上的 search 卡住

D4 的 heap 後續量到：同一顆引擎上第一輪（open、search、 click、insertText、save、close）成立，第二輪的 search 等滿 30 秒 不回來，之後每一次 search 都回 BUSY；兩個瀏覽器一模一樣。 沒有 search 的同一個迴圈跑完 8/8。但三個候選從來沒有被分開過：第二次 search 本身、中間的重新開檔、以及第一輪 search 之後那些 click／insert／save。這一頁一次動一個變數，四個 arm。 判準寫在 findings/evidence/sdk-e2/e2-c-validation/search-wedge/PREDICTION.md。 這一頁不判定。產品今天不走這條路（session 每次都建新引擎），所以這是 SDK 層的特徵化，不是對產品的宣稱。
