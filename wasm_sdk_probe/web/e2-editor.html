LiteCore 編輯器產品 v2 契約，十五個動作 啟動中
這是 E2-C 的產品頁面，跑在 — 上。 十五個動作（E1 的十個 ＋ E2 的五個）走的是**同一個 session、同一個 queue** ——`NarrowEditorV2Session` ＋ `NarrowEditorV2Client`。 這一頁釘死在上面那顆 artifact：換一顆 build 它會拒絕啟動。
拖曳選取走的是這一頁自己的指標處理器，不是合成事件——SPEC E2-C 的 D5 要的就是這條路徑上的真實 pointer event。
工具列不顯示這一段現在是什麼格式，這是刻意的（路線 C 不讀前置狀態， finding 022／021）。灰掉的按鈕代表manifest 沒有為這種選取宣告這個動作， 不代表它現在的狀態。
派送後驗不了的失敗，處置是回到檢查點，不是按復原——復原走的是同一條 被擋住的 queue（SPEC E2-B 5.13）。出現那種失敗時上面會跳出「回到檢查點」。
