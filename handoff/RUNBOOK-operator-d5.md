# 人工輪操作手冊 — E2-C D5 的四格

寫於 2026-08-16。**這一輪只做 D5 的四格。**

## 先講一件會影響你怎麼排時間的事

**E1-C 的收復這次不做**，而且不是排程問題。SPEC E1-C §11.8 的解除條件第 1 條是
「`e1-editor-v1` 的 relink 決定**作出之後**的第一個 operator 時段」——那個決定還沒
作出（它在等 v3 的參數化形式在產品上驗過，而 v3 的連結今天決定先等）。

現在做的話，若之後 `e1-editor-v1` 真的 relink，這兩輪人工**百分之百作廢**——
那正是 §11.8 當初把它延後的承重理由。**設置是一樣的，資格還沒到。**

## 為什麼這四格非要人不可

D5 整個相位的主題就是 `isTrusted`：瀏覽器會在每個事件上標記它是不是真人做的，
程式合成的一律是 `false`。我們的判定器**會據此拒絕**——這一點已經用機器那一半
證明過了（把補齊其他條件的那一格翻**一個**事件成合成，它就不過）。

所以這四格不是「還沒寫自動化」，是**自動化在定義上做不到**。

## 環境（四格都要，缺一格就少一格）

- **真的滑鼠**（拖曳選取要真的按住、移動、放開）
- **Fcitx5 新酷音**輸入法，能打中文並確定
- **真的剪貼簿**（系統剪貼簿，不是頁面內模擬）
- 瀏覽器**兩個都要跑一輪**：Chrome 與 Firefox

## 先講一件會讓你以為壞掉的事

**這個 build 不畫游標，也不畫選取反白。** 畫布只是文件的算圖，游標是引擎那邊的
狀態，而產品從來沒有把它畫出來（`e2-editor-app.js` 全檔 `caret` 只出現一次，
在註解裡）。

所以：**你在文件上按下去，畫面不會有任何變化。這是正常的，不是壞掉。**
2026-08-16 實測：點擊之後產品狀態維持 `ready`、沒有錯誤通知、事件有被記到——
游標**確實被放置了**，只是看不見。

**改看左邊那一塊即時讀數**（這一輪新加的）：

- `已記錄  pointerdown×1  pointermove×14  pointerup×1` —— 你的手勢被收到了
- `✓ 全部是真人事件` / `⚠ 合成事件 N 個 —— 這一格不會成立`
- `產品狀態 ready 修訂 3 generation 1` —— **按下項目符號之後「修訂」會加一**，
  那是動作真的生效的證據

**右邊也會把你剛才的指標軌跡畫在產品上面**：綠點是按下的位置、紅點是放開的
位置、藍線是中間走過的路徑。那層覆蓋不吃事件（實測 `pointer-events: none`，
畫面中央測到的仍然是產品的 iframe），所以它不會干擾你正在做的手勢。

## 第三、四格為什麼會「做了沒反應」——先看焦點那一行

中文輸入與 Ctrl+C／Ctrl+V **送到有焦點的地方**。你按左邊的「開始這一格」按鈕，
焦點就離開產品了；接下來真的按 Ctrl+V，事件會落在左邊那顆按鈕上，**什麼也不會
發生，而且哪裡都不會報錯**（這個 build 連游標都不畫）。

所以讀數多了一行，**每次做鍵盤或輸入法的動作之前先看它**：

- `✓ 鍵盤焦點在產品的輸入接收器（sink）` ← 這時打字／貼上才會進產品
- `⚠ 鍵盤焦點在這一頁（button）—— 先在文件上點一下`

**處方永遠一樣：先在文件內容上點一下，再打字或貼上。**

## 四格，每一格都是「按開始 → 做動作 → 按做完」

| 格 | 你要做的事 |
|---|---|
| `d5-pointer-drag-single` | 用滑鼠在**同一段**文字上拖曳選取，放開，按工具列的「項目符號」 |
| `d5-pointer-drag-cross` | 同樣的動作，但**跨兩段**；一樣按「項目符號」 |
| `d5-ime-commit` | **先在文件上點一下**（確認焦點那一行是 ✓），用新酷音輸入一次中文並確定；再拖曳選取一段文字、**再點一下焦點確認**、輸入一次取代它 |
| `d5-clipboard` | **先在文件上點一下**，拖曳選取一段文字，Ctrl+C；在別處點一下，Ctrl+V |

### 存檔現在不用你按了

凍結的判準對拖曳那兩格寫的是「**而且存出來的 ODT 看得到**」，而這一步
**三輪三敗**（第一輪沒寫進手冊、後兩輪存在頁面看不到的地方）。所以它不再是
你的步驟：**按「這一格做完了」時，harness 會先關掉那一格的事件視窗，再自己去按
產品的存檔鈕**，並把攔到的文件掛在剛結束的那一格上。

判準要的是「存出來的文件」，不是「誰按的按鈕」；而點擊發生在視窗關閉之後，
碰不到 `isTrusted` 的計分。已驗：12,197 位元組、ZIP 開頭、掛在正確的格子。

**第三格量過了**（2026-08-16，同一顆凍結引擎、產品自己的 commit 路徑）：
選取一段文字之後 commit，**存檔裡舊文字確實被取代**
（`E1-LC-ISOLATED` 消失、原位是新字）。所以「取代」這條路是通的——
看不到變化的時候，先確認的是焦點與選取，不是產品做不到。

**順序不重要，做完一格再開下一格就好。** 每一格：先按「開始這一格」，做動作，
再按「這一格做完了」。中間頁面會即時印出收到幾個事件。

## 做完之後（兩個按鈕，都要按）

1. **「全部做完，送出證據」**
2. **「把證據存成一個檔案」** → 會下載一個 JSON（metrics ＋ 所有存下來的文件）

**把那個檔案的路徑給我就好，其他都不用收。** 這個匯出路徑不是寫完沒跑過的——
機器那一半每次都會實際呼叫它一次並把結果記進證據（`operatorExport`）。

## 會發生的事，先講在前面

- **某一格做壞了可以重做**：再按一次「開始這一格」會覆蓋那一格的紀錄。
- **拖曳選取看不到反白**——同樣是因為產品不畫。用軌跡疊圖確認起訖點，
  再用「修訂」有沒有加一確認動作生效。
- **不要按到會跳出瀏覽器對話框的東西**（例如任何 confirm／alert）——那會卡住
  整個頁面的事件。
- **頁面不會判定**，它只記錄。判定是我離線跑分析器做的，判準早就凍結了。
- **IME 那一格請用 Firefox**：2026-08-16 兩瀏覽器對照量到 Chrome 會把
  `compositionend` 標成不可信（`isTrusted:false`），該格在 Chrome 上無法成立。
  這是平台限制，判準不因此放寬。
- 兩個瀏覽器各做一輪；哪一個先做都可以。
- **第一輪的紀錄已經留著當證據**（`d5/operator/round-1-chrome/`），沒有白做：
  它證明了 harness 會忠實記錄真人手勢（832 個事件），也量到產品的貼上與中文
  commit 在出貨 build 上**其實都生效了**（修訂號有動），只是看不見。
