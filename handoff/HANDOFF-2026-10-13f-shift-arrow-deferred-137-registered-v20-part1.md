Ruling 5 (`b0ca2790`) then ruled that typing and inline formats behind a pending arrow are reachable too. **Finding 137 is registered** (`57d16143`, broadened in `7606dc11`): *a document command sent behind an arrow key the core has not yet run can land on the wrong state*. There are three effects: **delete** (the wrong text is deleted, or one unit ahead), **typing** (the character lands one unit early) and **inline format** (applied to text the user had just deselected). It is reachable on **both 0.2.12 (the counted release) and 0.2.18 (today's uncounted candidate)**, because both run engine `e2-editor-v19` and the same `editor-shell/` input path. The precondition is a core-thread stall longer than the engine's 250 ms readback deadline, or longer than one page round trip, with the arrow and the next command typed inside it. It cannot be induced by any runner, its frequency has never been measured, there is **no interim patch** (every candidate is a timing bet), and the closure is the next spec, now named **"ordered commands"** (candidates A / A′ / B / C, §14 and below). Spec §13.3 shrinks v20 to: the page number, C without flag clauses, `caretBefore` as data, and the count.
