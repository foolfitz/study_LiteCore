# 人工輪操作手冊 — finding 065：按 Enter 之後格式還在不在

寫於 2026-08-21。**這一輪只做兩件事，加起來大約十五分鐘。**

## 為什麼要你來做

今天量到的 065 是這樣一句：**按 B、打字、按 Enter，剛打的那段字不再是粗體。**
自動化已經在 Chrome 與 Firefox 上各重現 100%——但**自動化打字走的是頁面上那個
「要插入的文字」欄位加「插入」按鈕**（`#text` ＋ `insert-text`）。

**你打字走的是另一條路。** 真人的鍵盤事件進 `#sink` 那個 textarea，經過
`beforeinput`／composition 走 `attachInput` 的輸入轉接器——和插入欄位是兩條不同的
程式碼路徑。這棵樹一整天的教訓就是「兩條路不同的時候，只有使用者那條沒被量過」
（049、050、Ctrl+C 三個缺陷都在那道縫裡）。

所以這一輪要回答的是：**065 對真正在打字的人也成立嗎？**

- 成立 → 065 從「harness 上量到的」升級成「使用者會撞到的」，而且看得見。
- 不成立 → 065 有一半是插入欄位那條路的產物，這張單要重寫。**這個結果同樣有價值，
  不要因為它「不是預期」就懷疑自己做錯。**

第二件事是**歸因方向**：同樣三個動作在**桌面版 LibreOffice** 上會不會掉。那決定
065 是上游的還是我們這一側的，而那件事目前完全沒有資料。

## 環境

- 真的瀏覽器視窗（Chrome 或 Firefox 都可以，兩個都做更好）
- 桌面版 LibreOffice Writer（第二部分用）
- **不需要**中文輸入法、不需要剪貼簿、不需要滑鼠拖曳

## 第一部分：產品頁上的三個動作

```bash
cd /home/jiajun/LibreOffice/study_LiteCore/wasm_sdk_probe
python3 web/serve.py --port 8791
```

在真的瀏覽器視窗打開：

```
http://127.0.0.1:8791/e2-editor.html
```

等狀態列變成 `ready`，畫布上出現文件。**這個 build 會畫游標，也會畫選取反白**
（finding 058 之後修好了），所以你點下去應該看得到游標——看不到就先說一聲，那本身
是另一件事。

### 步驟

1. 在文件中間某一行點一下，把游標放進一段文字裡。
2. 按工具列的 **`↵ 分段`**。游標會跑到一個新的空段落。
   （用按鈕不用 Enter 鍵，只是為了讓起點和自動化一致。）
3. 按工具列的 **`B`**。
4. **用鍵盤直接打** `MANUALBOLD`。不要用「要插入的文字」欄位，不要按「插入」。
   - **記下來：畫面上這幾個字看起來是粗體的嗎？**
5. 按 **`儲存 ODT`**，存成 `manual-1.odt`。
6. **按鍵盤的 Enter 鍵**（不要用 `↵ 分段` 按鈕——這一步就是要真人的按鍵）。
7. 再按 **`儲存 ODT`**，存成 `manual-2.odt`。
8. **記下來：畫面上 `MANUALBOLD` 那幾個字，現在還是粗體嗎？**

### 要回報的四件事

| | 回報 |
|---|---|
| A | 第 4 步打完，畫面上 `MANUALBOLD` 是粗體嗎？ |
| B | 第 8 步（按過 Enter 之後），畫面上 `MANUALBOLD` 還是粗體嗎？ |
| C | 兩個 `.odt` 檔的位置 |
| D | 全程有沒有跳過任何錯誤訊息、狀態列有沒有離開 `ready` |

**A 和 B 是這一輪的主結果，而且你的眼睛就是判準**——不必打開 ODT，我會去讀。
如果 A 就已經不是粗體，**停在那裡告訴我**，後面幾步不用做：那代表真人打字連
「格式有到打出來的字上」都不成立，那是比 065 更大的事。

### 加做一次（可選，兩分鐘）

同樣八步，但第 3 步改按 **`I`**（斜體），標記打 `MANUALITAL`。
065 目前只量過粗體，四個格式共用同一條派送路徑是**推論不是量測**。

## 第二部分：桌面版 LibreOffice 對照

這一段決定 065 要不要掛上游的帽子。**只要三個動作。**

1. 開桌面版 **LibreOffice Writer**，新建一份空白文件。
2. 打幾個字當背景，例如 `background`，然後按 Enter 換一段。
3. 按 **Ctrl+B**。
4. 打 `DESKTOPBOLD`。
5. **按 Enter。**
6. 看 `DESKTOPBOLD` 那幾個字**還是不是粗體**。

### 要回報的

| | 回報 |
|---|---|
| E | `DESKTOPBOLD` 在按 Enter 之後還是粗體嗎？ |
| F | 你用的是哪一版 LibreOffice（`說明 → 關於`，版本字串就好） |

**這一格不是定案，是方向。** 桌面版走的是 Writer 的 UI，和我們走的 LOK API 不是
同一條路，所以：

- 桌面版**也掉** → 強烈指向核心，值得排一輪真正的原生 LOK 對照來定案。
- 桌面版**不掉** → 就不能說是核心的通病，要往我們這一側的 `.uno:InsertPara` 路徑上找。

兩個結果都不足以單獨寫成上游單子——這棵樹的規矩是**沒有原生量測之前不指認層級**
（040、048、062 三次的前例）。這一格是決定「下一輪往哪個方向花力氣」。

- 不用比對 ODF、不用開壓縮檔。存檔交給我。
- 不用兩個瀏覽器都做——一個就夠回答主問題，第二個是加分。
