## 2. 新功能

### 2.1 Ctrl+Home／Ctrl+End（Mac：Cmd+Home／Cmd+End）跳到文件開頭／結尾（finding 142）

- 按 Ctrl+Home，游標移到文件開頭；按 Ctrl+End，移到文件結尾。畫面跟著捲過去。引擎新增兩個動作，id 22、23（規格 `SPEC-M3-link-batch-v21` §3.1）。
- **0.2.24 以前的危險沒了**：以前游標不動，以為自己在文件開頭再按 Backspace，刪掉的是游標實際所在處的字（0.2.24 發佈說明 §4.7）。
  - 0.2.26 上，這一下在宿主上以「什麼都不做」完成：revision 不變，存回去的文字等於原檔。已觀察：D2，宿主 0.2.26，Chrome 與 Firefox 各 3/3。
  - 同一臂在 0.2.24 上照舊會刪掉一個字：「LD-PAGE-01」變成「LD-AGE-01」，而且存回伺服器。已觀察：6/6，`shakedown/README.md` §5.8。
- **證明**：第 1 項的判準在兩個瀏覽器全部 PASS（D1–D14、E0，N=3，`findings/evidence/link-batch-v21/shakedown/README.md` §5）。D1 的母數是 38 臂，落點都和原生 Writer 一樣。
- **具名限制**（照規格要求寫出）：
  - **L-142-steps**：在表格或頁首裡，要按兩到三下才到文件開頭，一下走一層，和 Writer 一樣。頁首裡的 Ctrl+Home 在 WASM 上未量。
  - **L-142-readback-overtaken**：核心停頓超過 250 ms 時，移動會先以快取的游標回報完成。這時緊接著打的字、貼上、格式或刪除，可能搶在跳轉之前執行，落在移動前的游標處。這和 0.2.24 發佈說明 §4.1 的 finding 137 是同一類，根治在「有序指令」那一批。發生頻率未量。
  - **既有的一鍵殘留**（記錄、不判讀）：
    - Ctrl+Home 之後，在有項目符號、編號或縮排的第一段按 Backspace，等約 2.25 秒、什麼都不做（L-C-number-or-indent，0.2.24 §4.2）；
    - 在表格儲存格開頭按 Backspace，會被拒絕並重開（finding 136）。

## 3. 修好的問題

### 3.1 連按刪除鍵之後很快按方向鍵，下一個刪除落在點擊處（finding 150）

- **0.2.24 就有**。連按兩下刪除鍵，在 60 ms 內按方向鍵，再按刪除鍵：第二個刪除和最後的刪除會在當初點擊的位置執行，刪錯字。已觀察：V6e，0.2.24 兩個瀏覽器合計 6/6 出錯。
- 0.2.26：頁面在刪除還沒回答時，不再把引擎暫時的選取當成使用者的範圍。按鍵依序生效。已觀察：V6e 在 v21 頁面上 Chrome、Firefox 各 3/3 照順序（`shakedown/README.md` §5.1）。

### 3.2 改了內容之後按 Ctrl+Home／End，接著打的字落在原處（finding 151 的一半）

- 這是 v21 開發中途抓到的，沒有出貨過。Ctrl+Home／End 不再先存檢查點，所以「改內容 → Ctrl+End → 打字」的字落在文件結尾。已觀察：D14，兩個瀏覽器各 6/6。
- **另一半沒修，0.2.24 就有**：文件有未存的改動時，**改動後的第一下方向鍵**之後緊接著打字，字可能落在移動前那一行。已觀察：V8d，0.2.24 Chrome 3/3、Firefox 3/3。這一半被計數中的 finding 096 檢查釘住，留給「有序指令」那一批（fable 裁決 1）。

### 3.3 宿主裡被扣住的 Markdown 對話框蓋住編輯器（finding 154，只在 0.2.25）

- 0.2.25 上，Nextcloud 的全域樣式把頁面裡關著的「貼上為 Markdown」對話框顯示出來。它固定蓋在編輯器左上角：工具列左半和文件開頭被蓋住，點文件第一行沒有反應，「取消」也關不掉。
- 0.2.26 在宿主加一條規則修掉。已觀察：兩個瀏覽器，對話框不顯示，點擊落在文件上並定位游標（`findings/evidence/154/0226/`）。
- 0.2.25 沒有成為名義出貨版本，沒有使用者在出貨版上碰到它。

## 4. 已知、沒修、使用前要知道的

### 4.1 一段很長的段落會讓編輯器停止回應（finding 153，**0.2.24 就有**）

- **開啟含超長單一段落的文件並在其中打字，可能讓編輯器停止回應。**這句話是 finding 153 判準 4 要求寫的。
  - 「超長」約是 10 頁以上不分段，例如一篇沒有分段的長文或匯出的逐字稿。
  - 開檔本身正常；在那一段開頭打一個字，0.2.24 失敗 4/4，v21 失敗 2/2。已觀察，`findings/evidence/link-batch-v21/shakedown/diag-long-paragraph/`。
- 原因是引擎執行緒的 stack 只有 64 KiB，Writer 排長段落時的遞迴把它撐爆。一般的 Ctrl+V 有 16 KiB 上限，碰不到這條路。
- **修法要重新連結**，排在下一批 v22：只改 stack 大小這一個變數。

### 4.2 Markdown 貼上不在這一版（第 2 項；finding 153、152）

- 引擎 v21 裡有 Markdown 貼上，但**頁面不提供入口**。原因：一次貼上約 43 KB 以上的中文，就會撞上 4.1 的 stack 問題（finding 153）。
- 具名 **L-md-sdk-callable**：宿主或程式若直接呼叫 SDK 的 `pasteMarkdown`，仍然能用，也一樣會碰到 4.1。
- 對話框本身另有一個 Chrome 的焦點問題（finding 152：關掉對話框後打字沒反應）。入口沒開，所以碰不到。
- 修法跟 v22 一起：stack 修好、第 2 項重開、152 修掉。

### 4.3 0.2.24 發佈說明裡照舊成立的

- §4.1 finding 137（三種後果）、§4.2 兩個具名殘留、§4.3／§4.4 按住的尾巴、§4.6 Shift＋方向鍵不在這一批、§4.9 其他登錄：**都照舊**。0.2.26 沒有動方向鍵與刪除的路由，只有 150 的條件和 22／23 是例外。
- **§4.7（Ctrl+Home／End 不支援）由本文 2.1 取代。**
- §4.8 finding 135（打字延遲）：這次計數 C2 三輪都過。0.2.24 記錄的「Firefox 前幾鍵變慢」這次沒有出現：前五鍵提交中位數 22–26 ms，0.2.24 是 37–53 ms；畫面上最大 51.8 ms。只記錄，不推論原因（RESULT §C2）。
