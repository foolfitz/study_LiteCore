## Minimal implementation decisions for the later source phase

**One feature-only selector.** Use a dedicated `OXSDK_E2_V23_FEATURE_ABI6` compile define. It requires `OXSDK_E2_V23_LINK_BATCH` and is incompatible with `OXSDK_E2_V23_DIAGNOSTIC`; retain the existing transitive mainloop/v21 dependencies. Only the feature selector chooses `OXSDK_EDITOR_ABI_VERSION 6u` in editor_api.h and permits the four additional line-move actions in editor_api.cpp's extend-flag predicate. The existing v21 conditional remains the ABI5 fallback, and earlier variants retain ABI4. The shared ordered-engine define cannot select ABI6 because both diagnostic identities use it with ABI5. Do not alter the Document SDK's separate packed ABI version.

The six inherited external IDs are1,2,16,17,18,19, mapping to internal1–6. No enum allocation or maximum changes are needed: external maximum23, internal maximum25. The earlier ordered specification5.8 sentence about appending after25 must be explicitly corrected in the later append to mean new behavior on existing action IDs. The inherited six-action interface in link-batch4.1/4.2, corrected to ABI6 by its section18, is authoritative here. Do not invent new extend action names.

**Exact product identity.** The later target is `dist/profiles/e2-editor-v23/sdk-manifest.json`, with fresh objects and outputs in `build/e2/editor-v23`. Do not reuse r2 objects or overwrite its profile/archive. Same existing headless Writer core; no inferred a11y upgrade. Keep ordered dispatch/Q restoration, exclude diagnostic define/export/events/tails, and omit diagnostic STACK_OVERFLOW_CHECK2 as required by the existing feature-build checker. The owner performs the compiling make only after the later source/protocol/review/dry-run prerequisites. There is no runnable feature target today.

**Isolated product worker.** Create a new explicit source such as `sdk/v23-feature-worker.js`, copied from `build/archive/e2-editor-v22-f7a40bcc-worker-0d55bcfa/sdk-worker.js`, whose full base SHA256 is `0d55bcfa2ee0e4ddc6239e25282001c13410b152a5a08ebac9903cc65c3fd350`. Preserve a reviewed base-to-successor diff and verify the base hash during preparation. Use the complete product worker as the successor source; do not assemble it from a diagnostic tail or edit the current shared `sdk/sdk-worker.js`, which carries Calc changes. No Calc worker, profile, capability or installed host is part of this unit.

The necessary worker delta is narrow: editorActionV2's typed extend flag accepts the six moves under the ABI6 contract. Use a separate six-move predicate rather than silently redefining the old editorActionV1 predicate. Preserve exact manifest/runtime ABI handshake, every ID mapping, positive request-ID and uint32 revision checks, forbidden arbitrary key/UNO fields, enabled-format restriction, and error/result projection. The frozen worker's init already compares the runtime editor ABI to the manifest's declared ABI; there is no reason to replace that exact handshake with a numeric compatibility range. Keep the private diagnostic operation completely absent, not just unadvertised.

**Feature packaging wrapper.** A new profile-specific builder, for example `tools/build_e2_v23_feature_profile.py`, should call the existing v5/v4/c/b packaging chain with scoped overrides restored in finally blocks. Restrict it to the exact new profile. Do not edit old builders or their default identities. The existing v5 builder already supplies IDs1–23, inherited capability declarations and artifact bindings. Select ABI6 and apply only these action-contract changes: six moves gain all three existing gestures (mask7); remove `no-extend-selection` from16–19. Compare the complete resulting action/contract delta with pinned v22, allowing only those changes plus the ABI and actual artifact identities. Missing select-all is not withholding: action21 remains present with empty gestures/mask0. Document moves22/23 remain collapsed-only/no-extend; delete-selection20 remains range-only/mask6 with existing limitations; caret deletes3/4 remain collapsed-only. No other grants or capability additions follow from this design.

**Client and page compatibility.** Widen extension support only when the active manifest declares the successor contract; older profiles must not gain an advertised line-Shift path merely because a shared source file changed. Keep the same move completion/postcondition class for all six: unchanged revision, changed:false, accepted existing completion names, state from the post-flush reply. Line-move convenience methods/types need the existing boolean option, not a new SDK operation. The page sends shiftKey for the six keys and sends their unshifted range moves directly when the active manifest permits them. Writer decides collapse/landing; remove the preliminary point-click only for those six. Ctrl/Cmd document movements remain outside this expansion. Keep E1-C-bound base client/session files unchanged and inspect the bundle's actual dependency guard before edits.

Retain096 CHECKPOINTED_MOVES and its real save-before-first-dirty-move behavior. Retained-key/held-repeat handling must be based on actual admitted, queued and in-flight operations, not on the removed2.25s window or fabricated selection state. Preserve input order and the existing132 depth policy; do not copy withdrawn resolver flags/waiters by inertia. The exact retained-key per-cell predicate remains a required protocol decision below, not permission to add a generic queue architecture now.
