  不是特意去找的。
- 4b 的判斷半在計畫裡是**知情地**劃給人類判斷的，`CONSENT.md` 講得更直白：
  「an agent has no ears」。
- 4b 的**機械半**（游標移到哪、Orca 有沒有在那個當下唸出段落文字、標題有沒有

  細節在下面「開始前」與「4b 的判斷半」兩節。**你今天要判斷的是「聽起來對

## 2. 開始前

**這一輪釘住的候選頁面**：

```
9b29e39bb09e5b948937a7552bfad6045bdb4e25bb993ee1270ebe70dddf361c
```

這是 `e2-editor-v12`、shell generation v48 上的候選頁面，也是機械半的兩輪
Orca 走查（下面第 4 節）實際量過的那個頁面。

**開啟指令**（在終端機裡）：

```bash
cd /home/jiajun/LibreOffice/study_LiteCore/wasm_sdk_probe
python3 tools/serve_candidate_page.py --profile e2-editor-v12 \
    --expect-sha256 9b29e39bb09e5b948937a7552bfad6045bdb4e25bb993ee1270ebe70dddf361c
```

**這一步本身就是驗證**：這支工具會自己重新算一次候選頁面的 sha256，如果跟
`--expect-sha256` 對不上，它會直接報錯退出，不會把你帶到錯的頁面上。它印出來
的 JSON 裡也有一行 `"pageSha256": "..."`，值得親眼再核對一次跟上面那串一致。
指令跑起來之後會印出一行網址：

```
http://127.0.0.1:8765/e2-editor.html
```

用**真的瀏覽器**（不是任何自動化工具、不是無頭模式）打開它。畫面最上面那條
說明文字會寫「這一頁釘死在上面那顆 artifact」——那一格顯示的是 wasm 的 pin
（`4ec1e389aaab3b03…`），跟候選頁面的 sha256 是兩個不同的身分，兩個都對得上
才算數，但這次驗收釘的號碼是上面那個 sha256。

**出貨中的產品完全不受影響**：這個 server 只服務一份暫存鏡像
（`/tmp/candidate-round-*`），不寫入 `dist/`、`web/`、`sdk/` 底下任何一個
位元組。做完之後在終端機按 Ctrl+C 收掉就好，沒有東西需要復原。

**準備一份真的文件**：finding 086（下面條件 3 第 3 格會再提醒一次）只在一份
35 段、每段好幾百字的**真實**散文上量到過；九段的合成範例文件量不到同一個
狀態。建議整個六格都用同一份「有分量」的真實 `.odt` 文件做，而不是隨手打幾個
字。如果手邊沒有現成的，086 當時用的那一份還在，可以直接借用：

```
/home/jiajun/Documents/SLAT/e20-專訪瓦特老師.odt
```

用畫面上的「📂 開啟檔案」打開它（不是下拉選單裡的範例文件）。

**準備記筆記的地方**：開一個文字檔就好，不用是正式文件——下面「記錄」一節
會說放在哪裡。六格加上 4b 判斷半的四點，每一項寫一兩行就夠。

## 3. 條件 3 的六格

每一格都是「做動作 → 對照算過的標準 → 記下來」。**失敗不代表這一輪失敗**：
記下實際發生的事，繼續下一格。這是一次量測，不是除錯 session——看到不對勁
不要當場想辦法修好或重試到它變乾淨。

### 3.1 開檔

- **做**：按「📂 開啟檔案」，選一份真的 `.odt`（見上面「開始前」的建議）。
- **算過**：文件內容如實顯示；右上角狀態球回到 `ready`；沒有跳出錯誤 toast
  或「回到檢查點」的提示。
- **記下**：用的是哪個檔案（檔名就好）、開檔後狀態球顯示什麼。
- **失敗時**：把 toast／notice 的文字和狀態球顯示的字串原樣抄下來，繼續下一格。

### 3.2 打字（含一次 IME 上屏）

- **做**：在文件內容上點一下，把游標點進某一段文字裡；直接用鍵盤打幾個字；
  再切到中文輸入法，打一段需要選字的中文，按空白或 Enter 完成組字上屏。
  **不要用工具列上「要插入的文字」那個輸入欄＋「插入」鈕**——那是自動化測試
  走的路徑，跟使用者真的用鍵盤打字不是同一條路。
- **算過**：打的字元、上屏後的中文如實出現在游標所在的位置；狀態球維持
  `ready`。
- **記下**：打了什麼、IME 上屏那一下有沒有正確落在該落的位置。
- **失敗時**：記下實際打出來的內容跟你打的差在哪裡（截圖或文字描述都可以），
  繼續下一格。

### 3.3 段落格式 —— **先讀這段警語再動手**

- **做**：把游標點進文件裡一個**已經有文字、不是空段落、不是標題、不是清單
  項目**的普通段落，按工具列的「標題」。
- **算過**：那一段變成標題樣式；狀態球維持 `ready`；沒有跳出「回到檢查點」
  或「引擎需要重新開啟」。

**已知問題，finding 086**：在一份真實文件的普通段落上按「標題」，出貨中的
`e2-editor-v8` 跟候選 `e2-editor-v12` **都有機率**讓 session 直接掉進
`recoverable-error`——畫面會跳「這一步可能已經改到文件，而且無法驗證」
（候選這邊，通常還有檢查點可以回）或「引擎需要重新開啟，沒有檢查點」
（出貨這邊，通常沒有檢查點，上次存檔以來的內容救不回來）。

這不是這一輪才發現的新缺陷，根因已經量到底（判準用來認段落身分的指紋，剛好
定義在這個動作自己會改變的量上），而且**已經裁決延後到 cutover 之後才修**
（不算候選相對出貨的退步，兩邊都會發生，不會觸發 revert）。

**如果你按下去真的掉進這個狀態**：

1. 把 toast／notice 的文字、狀態球顯示的字串原樣抄下來。
2. 畫面如果有「回到檢查點」的按鈕就按下去；如果沒有，代表這一份文件在
   上次存檔之後的內容救不回來，重新開啟文件即可（用 3.1 同一份文件重開，
   或直接繼續往下做也可以，記一句「這格文件重開過」）。
3. 繼續做下一格。**觸發到 086 本身就是這一格合格的記錄**，不是操作失敗，
   不需要換一段文字重試到它不發生為止。

- **記下**：有沒有觸發 086；如果沒有，段落是否確實變成標題樣式。

### 3.4 選取後套用行內格式

- **做**：用滑鼠**真的拖曳選取**（按住、拖、放開；不要用 Ctrl+A 或雙擊代替）
  一段文字，選完之後按工具列上任一個行內格式鈕（B 粗體／I 斜體／U 底線／
  S 刪除線）。
- **算過**：選到的那段文字套上格式，畫面上看得出樣式差異；狀態球 `ready`。
- **記下**：選了哪一段、套了哪個格式、有沒有生效。
- **失敗時**：記下實際狀態，繼續下一格。

### 3.5 undo / redo

- **做**：對剛剛任一個生效過的動作（例如上一格的格式，或打字）按「↶ 復原」；
  如果「↷ 重做」按鈕有出現在工具列上，再按一次它。
- **算過**：復原後那個動作的效果消失，文件回到動作前的樣子；如果有重做按鈕，
  按下去能把效果變回來。
- **記下**：復原、重做各自有沒有生效；**如果工具列上根本沒看到「重做」按鈕**，
  寫「沒看到重做按鈕」就好——這顆鈕在部分 profile 上本來就不出現，先記下有
  沒有看到，不用自己判斷這算不算異常。
- **失敗時**：記下實際狀態，繼續下一格。

### 3.6 存檔後重開

- **做**：按「儲存 ODT」，把檔案存到你電腦上；再按「📂 開啟檔案」，把剛剛
  存出來的那個檔案重新打開。
- **算過**：重新開啟後，文件內容（包含前面幾格打的字、套的格式、標題等，
  如果 3.3 沒有炸的話）都還在；沒有跳出錯誤。
- **記下**：存出來的檔案名稱／路徑；重開後內容跟存檔前是否一致。
- **失敗時**：記下差異即可——這是最後一格，做完就進第 4 節。

## 4. 4b 的判斷半

**先講清楚已經做完的部分**：4b 的**機械半**——游標移動時 Orca 有沒有在當下
唸出段落文字、標題有沒有帶著角色與層級被唸出來——已經由 agent 在這個候選頁面
（`9b29e39b…`）上用同一支走查工具連續走了兩輪，並且對照了修好之前的舊頁面
當控制組（見
`findings/evidence/manual-round-v12d-9b29e39b/RESULT-4b-v45-vs-v46.md`）：
十段全部唸到、第二個標題之後那一段殘留的重複朗讀不再出現，而同一個 session
裡舊頁面的對照組仍然會重複——這證明不是儀器壞了、是這個頁面真的修好了。

**所以今天你要判斷的不是「有沒有在唸」，是「唸起來對不對」——這是唯一沒辦法
叫機器代勞的部分，因為機器沒有耳朵。**

**做**：打開 Orca（畫面朗讀器），確認前景只有這一個候選頁面的分頁（其他視窗、
分頁先關掉或切開，免得干擾你判斷唸出來的東西是不是文件本身），用方向鍵在
文件裡走一遍，至少經過一個標題、一個清單項目、還有普通段落，走完關掉 Orca。

**要回報的四件事**（計畫原文列的三項判斷，加一份點名要聽的殘留清單）：

1. **唸的順序**——段落、角色（標題／清單項目）、內容彼此唸出來的先後順序
   聽起來順不順。
2. **囉唆程度**——同一件事有沒有講太多次、太瑣碎，聽起來累不累。
3. **瀏覽模式（browse mode）底下的行為**——方向鍵在瀏覽模式下走的感覺是否
   正常，有沒有卡住、跳步或反應遲鈍。
4. **點名要聽的殘留清單**——清單項目的符號（`•`、`1.`）有沒有被唸兩次
   （這是已知候選項 `queue-list-prefix-read-twice`）；段落文字很長時唸出來
   的地方有沒有被截斷的痕跡（背景：頁面唸出的段落文字有 4096 字元的上限）。

**這半不會擋下 cutover**：不管聽起來怎樣，寫下你聽到的就好，不用判斷「這樣
算不算過」。如果你今天完全沒辦法操作 Orca，寫「沒做」也是合法答案——計畫
本身就允許這個退路，只是會被記成延後到正式對外展示之前再補一次，不是說
今天一定要生出一個結果。

## 6. 出事怎麼辦

**這一格作廢、重做**（環境問題，不算失敗）：中途被別的事岔開、瀏覽器分頁或
視窗切換到別的東西、跳出跟這次操作無關的對話框、瀏覽器當掉重開——這些是
「儀器或環境髒了」，不是產品的行為。記一句作廢原因，重開那一格再做一次即可。

**這是真的失敗，照抄、不要重試到乾淨為止**：產品自己跳 toast／notice 說錯誤、
掉進 `recoverable-error`、內容跑掉、格式沒套上——這是量到的東西，原樣抄下來，
繼續下一格。**不要因為結果不好看就換一份文件、換一個動作重來，直到它變乾淨。**

**如果一開始頁面 sha 就對不上**：`serve_candidate_page.py` 會直接報錯退出，
代表樹在你要開始之前又動過了。**不要繞過這個檢查、不要拿舊的 sha 硬做這一
輪**——先回報，等確認清楚之後再開始。

**如果做到一半才發現不對勁**（比如中途重新整理過瀏覽器、換了埠號、或懷疑樹
被誰動過）：整輪視為作廢，這一份筆記不算數，等重新確認乾淨之後，六格＋4b
從頭做一次。

**最重要的一條**：這一輪存在的理由就是要抓出自動化抓不到的東西——086 就是
這樣被抓到的，不是特意找出來的。**抓到一個真的壞掉的東西，比一輪從頭到尾
乾淨的紀錄更有價值。**照實記下來就好，不要為了讓這一輪看起來乾淨而重試。
