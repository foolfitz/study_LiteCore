## 2. 新功能

### 2.1 貼上為 Markdown（第 2 項）

- **怎麼用**：工具列「貼上為 Markdown…」→ 對話框 → 把 Markdown 文字貼進框裡 → 「插入」。按「取消」什麼都不會變。〔讀原始碼：`web/e2-editor-app.js`；已觀察：M11 取消臂〕
- **轉出來的結構和桌面 Writer 一樣**：原生語料裡掃描判定可以貼的 29 項，貼到空文件開頭後，存檔的結構與原生 LibreOffice 貼上的相同。兩個瀏覽器各 29 項 × 3 輪 = 87 格，全過。〔已觀察：E2 的 M1〕
- **中日韓文字不亂碼**：存檔文字等於原生 `zh_TW.UTF-8` 的。〔已觀察：M2〕
- **一次復原就回到貼上前**，原有的格式也一起回來。〔已觀察：M4。38 個收合游標位置、14 個範圍、5 個受保護位置，共 57 臂 × 3 輪 = 171 格，兩個瀏覽器全過〕
- **大段也快**：64 KiB 的語料從「忙碌」到「就緒」，Chrome 0.36–0.66 秒、Firefox 0.54–0.59 秒，一次復原就還原。〔已觀察：M6〕
- **會拒絕、而且什麼都不改的情況**。以下幾種都回明確的拒絕，文件內容、版次、復原紀錄都不變：
  - 含遠端圖片或 HTML 的 Markdown；
  - 內容是空的、有 NUL、解析失敗；
  - 超過 65,536 位元組（UTF-8）。

  〔已觀察：M3，Chrome 201 格、Firefox 189 格全過〕

  遠端圖片與 HTML 那幾項**不會連線到裡面的網址**：瀏覽器網路紀錄對目標主機 0 個請求。〔已觀察：M5，對照組有抓到 `probe.wasm`〕
- **有選取範圍時不貼**，請先取消選取。只選一張圖片、選一個外框、跨儲存格選取，也都拒絕。〔已觀察：M4 的範圍臂、M10〕
- **受保護區段**照預先寫好的規則處理：結果未知時走回復，回復之後文件不變；先打過還沒存的字會保留。〔已觀察：M9〕
- **一般的 Ctrl+V 照舊**，Markdown 符號照字面貼上。〔已觀察：M7〕
- **貼上之後文件標成已修改，會自動存檔**：在 Nextcloud 裡貼上後不再動，約 30 秒自動存檔，存下的檔案含貼上的那一段。〔已觀察：M11；宿主 0.2.27 上 M11-autosave，Chrome 30.6 秒、Firefox 30.2 秒，各 3/3〕
- **只有宣告了 Markdown 貼上的引擎才有入口**：搭沒有這個功能的引擎時，按鈕藏著，SDK 也拒絕。〔已觀察：M8〕

## 3. 修好的問題

### 3.1 一段很長的段落、或一大段中文 Markdown，會讓編輯器停止回應（finding 153，**0.2.24 起就有**）

- 0.2.26 發佈說明 §4.1 的那句「開啟含超長單一段落的文件並在其中打字，可能讓編輯器停止回應」，**這一版拿掉**。
- 原因是引擎執行緒的 stack 只有 64 KiB，v22 改成 1 MiB。
- 驗收用四個輸入：65,536 位元組的單段中文 Markdown、43,520 位元組的中文、65,536 位元組的 ASCII、一個 14 頁的單段文件裡打字。兩個瀏覽器各 3 回，**24/24 全部正常完成**，24 份存檔都把整段完整存進一個段落。
- 同一天同一工具，v21 在同一個輸入上，兩個瀏覽器都當掉。〔已觀察：C1，規格 §10.1〕

### 3.2 Chrome 裡關掉 Markdown 對話框之後，接著打的字沒有進文件（finding 152）

- 修法 3：關對話框時先讓輸入框失焦，再重新聚焦。
- 驗收的四種情境：「插入」關掉對話框後 0 ms 與 300 ms 打字；開了對話框直接「取消」再打字；有選取範圍時「插入」被拒、再「取消」打字。兩個瀏覽器各 3/3，字都進了文件。〔已觀察：F3〕
- **擁有者在真的 Chrome 上的手測還沒做**（第 6 節）。

### 3.3 Nextcloud 裡，關著的對話框不會露出來、不會擋點擊（finding 154）

- 0.2.26 在宿主加了一條規則，這一版頁面自己也加了同樣的規則。
- 在 0.2.27 上，就緒時與取消之後，對話框都不顯示。在文件第一行點一下會放游標。入口按鈕看得到。〔已觀察：H-154c，兩個瀏覽器各 3 輪〕

### 3.4 Nextcloud 裡，打開的「貼上為 Markdown」視窗會出現在畫面中央（finding 155，0.2.28）

- 0.2.27 上，它出現在畫面左上角，中心偏離 [−605, −322.5] px。原因是 Nextcloud 的 CSS 把對話框的 `margin` 歸零。
- 0.2.28 在宿主加了一條規則改回置中。兩個瀏覽器各 3 輪，中心偏移 Chrome [0, +0.5]、Firefox [0, 0]，判準是 16 px 以內。打開時焦點在文字框，「插入」「取消」都按得到；關著時看不到。〔已觀察：H-155、H-154o、H-154c，`findings/evidence/host-0.2.28/judge-h155.txt`〕

## 4. 已知、沒修、使用前要知道的

### 4.1 stack 溢位沒有人檢查（具名 L-153-no-overflow-check）

- v22 沒有開 Emscripten 的 `STACK_OVERFLOW_CHECK`。如果還有比 1 MiB 更深的遞迴，症狀會是崩潰、停住，或晚一點才出現的中止，而不是一個清楚的錯誤訊息。〔讀原始碼：規格 §3.3〕
- 記憶體：引擎執行緒的 stack 是 1 MiB，每一條活著的執行緒從固定 1 GiB 的 heap 用掉約 1 MiB；常駐的 pool 有 7 條，共 7 MiB。〔推論：規格 §3.2、§8〕

### 4.2 大段貼上之後立刻 Ctrl+End 再打字，先後次序不保證

這個情境沒有量過（D6 沒有實作），這一版**不對它的先後次序做任何宣稱**。〔未量〕

### 4.3 Nextcloud 裡藏起來的開發者控制項

宿主藏起來的部件清單是手寫的 16 個 selector，逐元素讀過，但**沒有經過 DOM 普查**。〔讀原始碼：`templates/editor.php`；規格 §11.1〕

### 4.4 0.2.26 發佈說明裡照舊成立的

- §4.3 列的（finding 137、按住的尾巴、Shift＋方向鍵不在這一批等）**都照舊**。v22 沒有動方向鍵與刪除的路由。
- §4.1 由本文 3.1 取代，§4.2（Markdown 貼上不在這一版）由本文 2.1 取代。
