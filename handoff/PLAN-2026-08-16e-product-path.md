# 計畫 2026-08-16e — 把「使用者那條路」變成會跑的東西

承接 [`HANDOFF-2026-08-16d-d5-complete.md`](HANDOFF-2026-08-16d-d5-complete.md)。

## 這份計畫要解的問題

昨天三個缺陷（049 存檔、050 IME、Ctrl+C）**全部躺在同一道縫裡**：每個 harness
都自己呼叫 `session.save()`／`commitText()`，所以產品頁面那條路從來沒有被走過。
處方寫進了記憶，但**記憶不會在 CI 裡變紅**。這份計畫把它變成會跑的檢查。

同時把兩次「判定器比它自己的 oracle 弱」補起來——**只對第二輪生效**，不追溯改判。

## 任務

### T1 — 產品那條路的回歸 harness（最高價值）

`tools/run_e2_c_page_smoke.py` 今天只碰兩件事：點一下、按一顆段落鈕。**三個缺陷
沒有一個在它的路徑上。** 擴成 `tools/run_e2_c_product_path.py`，走產品頁面自己的
處理器，蓋住三個缺陷的形狀：

1. **存檔鈕**（049 的形狀）：按產品自己的鈕，用**申報過的** `URL.createObjectURL`
   shim 攔位元組 → 開頭必須是 `PK\x03\x04`、長度合理、產品提示列不是 `NaN`
2. **三次 IME commit**（050 的形狀）：對 `#sink` 送三組合成事件（真的走 adapter 的
   composition 路徑）→ **修訂號要前進三次**，且三串字都在存出來的文件裡
3. **Ctrl+C**（第三個缺陷的形狀）：送一個 `copy` 事件 → 產品必須**去問引擎**
   （沒有選取時給出有型別的錯，而不是沉默）

**驗收（沒有這條就只是裝飾）**：把每一項的修法在 `dist/` 的暫存副本裡**還原**，
對應的那一項必須變紅、其餘不受影響。三個突變、三次紅、一次全綠。

**必須寫清楚的縮限**：合成事件是 `isTrusted:false`，**這不是 D5**，不得拿來充當
任何一格人工判準。它是回歸網，不是相位格。

### T2 — D5 判定器補上兩個缺口（只對第二輪）

`analyze_e2_c_d5.py` 兩次比凍結的 oracle 弱（round 4 只看有沒有攔到檔、round 5 只
問修訂號動過沒有）。加 `--criteria round-two`：

- 拖曳兩格：**打開存出來的文件驗結構**（`text:list` 計數／指名段落的樣式）
- IME 那格：**oracle 指名幾次 commit 就要前進幾次修訂號**

**驗收**：強化模式必須**判 round 5 為 NOT_ESTABLISHED**（弱判定器給過它）、
**判 round 6 為 PASS**。預設模式對第 1–6 輪的輸出**逐位元不變**。

順帶把 round 4 的落差寫進 `validation-matrix-v2-draft.json` 的兩格拖曳
（今天只寫在證據散文裡）。

### T3 — D5 機器半邊在 v6 殼層上重跑

D5 的四格人工跑在 v6、機器半邊跑在 v3。**這一格自動化跑得動**，跑完 D5 這個相位
內部就在同一代殼層上。驗收：判定與 v3 相同；**不同就是一個 finding**。

### T4 — search-after-reopen 卡住：特徵化

五個未做佇列項裡唯一「不知道它是什麼」的一項。先登記預測，再二分：是第二次 search、
還是 reopen 之後的 search、還是第 N 次 reopen。驗收：佇列項的 note 能指名**哪一個
變數移動它**。

### T5 — `.uno:SelectText` 選過頭：邊界擴大 ＋ 修法設計 ＋ 事前預測

量到的是「只有空段落」。擴到：文件最後一個空段落、清單裡的空段落、兩個清單之間的
空段落、只含一個空白字元的段落。然後把修法（改用 block identity 驗，而不是拒絕）
與**它的驗收預測**寫下來——趁 relink 還沒發生，預測才有事前性。

### T6 — codex 對抗性審查

T1 與 T2 做完之後發包：**哪一項檢查不可能變紅？哪一格的 PASS 靠的是判定器而不是
oracle？** 回來的每一條我自己重跑再採信。

### T7 — 收束

結果回填這份計畫、記憶更新、一份交接。
