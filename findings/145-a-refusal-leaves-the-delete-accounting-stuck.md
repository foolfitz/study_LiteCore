## 機制

1. 一次刪除被引擎拒絕（例：merge 案例 C15–C17；使用者的路上例如表格儲存格末端按 Delete，finding 136）→ 頁面重新開檔 → `session.document` 換成新的物件。
2. 那次刪除的 `settleDelete` 看到文件換了，直接 return，`deletesUnanswered` 留在 1。這個頁面之後的生命期裡它都不會再回到 0。
3. 之後只要按下的鍵等於「上一個送出的鍵」，`holdsDelete` 就扣住（`heldDeletes.count += 1`），什麼都不送，畫面上是「按了沒反應」。
4. 按另一個鍵時它會送出，等引擎回答後，`releaseHeldDelete` 把扣住的次數**用這個新鍵的動作**一一重送，於是多刪。

merge 計數的實例：Y02、D01 兩次 Delete 被扣住，接著 D04 的一次 Backspace 刪了 3 次；下一輪 C01 的一次 Delete 也刪了 3 次（前面扣了 D08、D12 兩次 Backspace）。

## 使用者的路（未量）

v20 的文件兩端已經不拒絕（C），但拒絕仍存在：表格儲存格末端的 Delete（finding 136）。推論：使用者在表格儲存格末端按一次 Delete（看到拒絕的提示與重新開檔）之後，再按 Delete 都不會有反應；接著按一次 Backspace，就會刪掉「1＋之前按的 Delete 次數」個字。

**未量**：production UI 沒有任何臂會在 v20 上誘發拒絕（`SPEC-M3-link-batch` §17.3：B3x 撤出、A1-2′ R 跨拒絕的救援登錄為無人守著）。下一個量測是宿主上的手測或探針。
