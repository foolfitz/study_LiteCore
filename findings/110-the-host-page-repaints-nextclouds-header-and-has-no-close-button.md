## 現象與量測

Nextcloud 的頂欄是透明的，白色圖示畫在 `body` 的主題背景上。檔案頁的 `body` 背景是主色 `rgb(0, 103, 158)` 加主題背景圖；編輯器頁面
被產品樣式換成 `rgb(244, 246, 248)`、沒有背景圖——白色圖示落在淺灰上，幾乎看不見。產品樣式也改寫了 Nextcloud 自己的按鈕與輸入框。
richdocuments 有標題列與關閉鈕；我們的宿主沒有，使用者只能按瀏覽器的上一頁。

證據：`evidence/110/`。

## 處置方向（未決）

宿主把產品樣式限縮在自己的容器裡（`body` 的規則改套到容器、全域元素選擇器加上容器前綴），並加一條標題列：檔名＋關閉鈕（回到檔案；
離開前的未存詢問照現有的頁面誠實化規則走）。只動宿主，不動產品頁面的位元組；但宿主改版要照慣例升版、六支 M3 runner 重新計數。

## 現況（2026-10-06，只追加；狀態欄照裁決維持「未修」）

修法在宿主 0.2.6／0.2.7（`0488586`）：產品樣式用 CSS `@scope` 限縮在 `#litecore-editor-root` 裡，加了標題列（檔名＋關閉鈕），開發用
控制項藏起來。2026-10-06 在 0.2.7 上計數通過 `SPEC-M3-production-ui` 的 A 列：停用產品樣式前後，頁面上 285 個元素（容器內外合計）逐一比對瀏覽器
自己列出的全部屬性（Chrome 1065／Firefox 974 個），容器之外**零個元素改變**、容器之內 87 個改變（A2-1）；編輯器頁 `body` 的背景與 Files 頁相同（A2-2）；關閉鈕回到
`/apps/files/files/<id>?dir=/`、鎖 0.3 秒內解除，有未存修改時宿主會問（A2-3）。不支援 `@scope` 的瀏覽器退回未限縮的樣式：編輯器能用、
不露出內部元件，但頂欄又會被蓋（規格 §9.6，具名代價）。

**還不能標已修**：同 109——規格 §4 的 R 列裡 locks 那一支紅了一格（finding 112），重跑一次（規格 §12）綠了才改成已修。
