# 094 — 產品頁面的 HTML（以及裡面每一條 CSS）沒有被任何東西綁住

**狀態**：靜態確認，2026-09-08。由 finding 093 逼出來——093 的成因住在一個
**沒有任何檢查在看**的檔案裡，這件事是查它的修法要花多少代價時才發現的。

## 宣稱

`wasm_sdk_probe/web/e2-editor.html` 的位元組，**不被這棵樹的任何閘門機制雜湊**。

逐項核過：

- **shell bundle 從來沒有收過它。**`e2/editor-shell-v2-bundle-v1.json` 到
  `v48.json`，每一代的 `included` 都是 12 或 13 個項目，**副檔名全是 `.js`**，
  html 項目數在每一代都是 0。
- **`servedSha256` 看不到它。**`run_e2_c_product_path.py` 的
  `served_shell_identity()` 只走 `manifest["included"]` 那份清單
  （`tools/run_e2_c_product_path.py:2303`），所以清單以外的檔案不進摘要。
- **`candidateCutover.pageSha256` 也看不到它。**那串雜湊算的是
  `web/e2-editor-app.js` 重新指向候選 profile 之後的位元組
  （`build_cutover_page.py`），不含 HTML。
- **十一支 `check_*.py` 沒有一支讀 `.html`。**`tests/test_r8_*.py` 出現的
  `.html` 指的是 R7／R8 交付線的 `r7-reference.html` 與逃逸路徑測試，不是這一頁。

## 為什麼這是缺陷，而不是「本來就不需要」

**這一頁的行為有一半住在那個檔案裡。**每一條 CSS、每一個 DOM 節點、每一個
`role` 與 `aria-label` 都在 HTML 裡；`e2-editor-app.js` 只是操作它們的程式。
finding 093 就是純粹的 CSS 缺陷——`.a11y-only` 少了 `top`／`left`——而它讓
無障礙投影在日常方向鍵瀏覽下把視窗釘在頁面底部。

這個洞有**兩個方向**，兩個都要說：

1. **十二趟乾淨的 soak 會宣告一個不含這個檔案的身分。**報告裡的
   `pageSha256` 與 `servedSha256` 都對得上，而那一頁實際被使用者看到的樣子，
   有一半不在這兩串數字的涵蓋範圍內。
2. **反過來更嚴重：改動這個檔案不會動到任何被釘住的摘要。**閘門的規則是
   「動到那三條就從零重來」，但守衛根本沒有在看這個檔案，所以一個**會改變產品
   行為**的編輯可以落地而計數不歸零——不是因為它無害，是因為沒有人在看。

第 2 點現在就要用到：093 的修法正是這種編輯。**「修了不用歸零」如果成立，
理由必須是裁決說它不算，不能是「守衛剛好沒在看那裡」。**

## 判別法（AGENTS.md §1 的動態判別）

往真值源塞一個虛構的新成員，看哪個檢查轉紅：**在 `e2-editor.html` 裡改一條
CSS 規則，零個檢查轉紅**，而「這十二趟跑的是同一個頁面」這句宣稱已經假了。
這是手工枚舉的那一種——成員（哪些檔案算數）住在別處（bundle 的 `included`
清單），而清單是手維護的。

## 處置：**不在這一輪修**

補綁 HTML 會改變 `servedSha256` 的定義，那是**動到判準本身**，而閘門正在跑。
AGENTS.md §9 允許跑動中新增判準，但要四個條件同時成立；這一條**沒有先於滿足**
——已經押了六趟。所以：

- 現在**只登錄**，不補機制（§4 的自察條件：發現自己在寫新機制就停手回報）。
- 補綁的時機是 cutover 之後，與 093 的修法一起；那時 `servedSha256` 的定義
  變更本來就要伴隨一次新的 generation。
- 在那之前，**任何對 `e2-editor.html` 的編輯都必須被當成會歸零的編輯來處理**，
  由裁決逐案決定，不得因為「檢查沒紅」就當作沒發生。

## 清點：編輯器頁面還會拉哪些沒被綁的檔案（2026-09-10）

原「未做」要求清點還有哪些**被服務但不在 bundle** 的檔案會餵進這一頁。查了三處：
`e2-editor.html` 的靜態引用、產品檔案圖裡的執行期 `fetch`／動態 `import`、以及
`web/` 底下實際存在的非 JS 資產。

- **`e2-editor.html` 本身不引用任何外部資產。**整份只有兩個外部參照：一個內嵌
  `<style>`（第 6 行）和一個 `<script type="module" src="./e2-editor-app.js">`
  （第 330 行）。**沒有** `<link rel=stylesheet>`、`<img>`、外部字型或圖示。所以
  這一頁的每一條 CSS 都**內嵌在 `e2-editor.html` 裡**——本張原本點名的那一個檔案
  已經涵蓋了這一頁全部的 CSS，沒有另一個獨立的 CSS 檔漏在外面。
- **`web/r6.css`、`web/r7.css` 確實存在但不屬於這一頁。**它們是 R6／R7 reader
  殼層的樣式，`e2-editor.html` 不引用；不是編輯器產品頁的一部分。
- **執行期只拉三種東西，都不是「沒被綁的產品行為位元組」**：
  `./e1-fixtures/<name>` 與 `./e1-fixtures/manifest.json`（`e2-editor-app.js:1634`、
  `:1670`）是**測試輸入的 fixture**，由使用者透過檔案輸入開啟，不是定義出貨頁面的
  位元組；`./sdk-worker.js`（`document-sdk.js:85-86`）是 worker，**已由 manifest 的
  `workerSha256` 綁定**。bundle 的靜態 import 圖已經封閉（`reachable()` 檢查
  reached-not-in-bundle 為空），沒有漏掉的動態 import。

**結論：`e2-editor.html` 是唯一一個「會定義這一頁外觀與行為、卻落在雜湊網外」的被
服務檔案。**它的 CSS 內嵌在它裡面，所以本張原本的宣稱已經完整——沒有另外的未綁
CSS 檔、圖示、或 worker HTML 殼層餵進這一頁。第 2 點的洞（改這個檔案不會動任何被釘
住的摘要、計數不歸零）維持不變，處置也不變（cutover 時與 093 一起補綁）。

**誠實的界限**：`e1-fixtures/` 底下的檔案確實被服務且未綁，但它們是測試輸入不是
出貨頁的組成，已在上面區分。另外只清點了**編輯器這一頁自己的圖**；其他診斷／demo
頁各有自己的未綁 HTML，那些不是產品，不在本張範圍。
