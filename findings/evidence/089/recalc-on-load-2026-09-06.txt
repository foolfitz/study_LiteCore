                aQueryBox.hide_ask();

            bHardRecalc = aQueryBox.run() == RET_YES;

            if (aQueryBox.get_active())
            {
                // Always perform selected action in the future.
                std::shared_ptr<comphelper::ConfigurationChanges> batch(comphelper::ConfigurationChanges::create());

                aOpt.SetODFRecalcOptions(bHardRecalc ? RECALC_ALWAYS : RECALC_NEVER);
                /* XXX  is this really supposed to set the ScModule options?
                 *      Not the ScDocShell options? */
                mod->SetFormulaOptions(aOpt);

                batch->commit();
            }
        }
    }
    else if (nRecalcMode == RECALC_ALWAYS)
        bHardRecalc = true;

## 8. Why section 4 is not vacuous

The same dd/split method prints `<value>0</value>` for the neighbouring prop
`RecalcOptimalRowHeightMode` in the same package (section 4, line 7).  So the
reader can see the method distinguishes 0 from 1 in this file; a method that
could only ever print `1` would be worth nothing here.

## What this establishes, and what it does not

ESTABLISHED: the ODS load path does not call `DoHardRecalc()`.  `bHardRecalc`
is false on this profile, and would be false natively too, for the same reason
(the default is shared).  The product-side hypothesis is DISCONFIRMED: the SDK
does not force a recalculation that native skips.

NOT ESTABLISHED: that no computation happens at load.  The `else` branch still
runs `Broadcast(ScHint(SfxHintId::ScDataChanged, BCA_BRDCST_ALWAYS))`, and the
99 cells carry no cached result, so they are dirty and must be interpreted on
either platform.  This measurement removes one candidate for the 670x gap; it
does not name the cause, and nothing here should be read as naming one.
