Symmetric: satisfied -> verified (record shows `multiBlock:true`, which is the honesty requirement, already met by the serializer); not satisfied -> `postcondition-not-met` / `EDITOR_FORMAT_POSTCONDITION_FAILED`, rollback disposition, exactly as a text paragraph today. I considered keeping `review` for the not-satisfied multi-block case and reject it: the premise's confidence is the same in both directions, and a second branch is a new mechanism (CLAUDE.md §4) that would hide a genuine failure behind "could not verify".
- **Q1.3 The premise (P1): the cursor is in the dispatch paragraph when the select runs.** Answered by source for the select (Q2 list above: start never leaves the cursor's node; overshoot forward, once) and, with G, reduced to "the dispatch does not move the cursor across nodes" -- measured for `.uno:DefaultBullet` (G = F, 8 cells x 5) and to be measured for the other four commands (Q6.3) before scope is pinned. Under F the same premise rests on a geometric restore after the paragraph's geometry was just changed by the action -- the weaker footing (Q2).
- **Q1.4 The premise (P2): parser semantics as read** (first structural tag decides listTag; first block tag decides blockTag; `<br/>` inside an open block is ignored). Pinned by a unit test on the recorded HTML (Q6.2), not by a sentence.

- **Q1.6 046's rejection reasons.** (a) "one engine twice, one shape" -> now a second core build (native 671c848b vs the browser runs), 16 multi-block shapes x 5, including shams and the already-bulleted neighbour; (b) "upward overflow onto an already-bulleted paragraph" -> by source the start cannot move up; n3 shows the paragraph above is never in the read; n2 shows a bulleted NEIGHBOUR in the read does not satisfy the predicate when the action did nothing. ## 5. 給擁有者（白話）

空白行按項目符號會跳提示，是因為引擎核對時用來「選取這一段」的那個指令，在空段落上一定會多選到**下一段**，引擎就老實說「我看到兩段，分不清」。這次我查了 LibreOffice 的原始碼，也看了原生量測：那個多選**只會往下、剛好一段、絕不會往上**，而且讀回來的第一段就是你游標所在的那段（16 種形狀各量 5 次都對，連「隔壁本來就是項目符號、動作其實沒做」的陷阱也分得出來）。所以下一次改引擎（v27）就讓它**只看第一段**來判斷，這一格的提示會消失、下方會顯示時間；順便把核對前那一步「把游標搬回原位」拿掉，改成直接從動作做完的位置核對，比較不怕版面變動。**但全新空白文件那一格還是會有提示**：那是文件的最後一段，後面沒有東西可以多選，引擎什麼都讀不到，只知道「有一步可以復原」——那不算核對過，我不接受拿它當成功；要拿掉那個提示得另外量一種選取方式，排到之後。規格寫之前還要先補跑五個原生小格子（幾分鐘、不碰 ddev），確認「標題改內文」等另外四個動作也一樣安全。
