## 1. Ruling in one paragraph

**Fallback = `.uno:CharLeftSel` only, on the collapsed route only, only after `.uno:SelectText`'s synchronous read is NONE, inside the same ordered command, before the existing Q restore.** Its readback is judged by a **new last-block predicate** on two new `FormatReadback` fields (`lastListTag`, `lastBlockTag`), with the existing structural refusals plus one new one (`blockCount != 2`), and the existing `restoreConfirmed`. ## 3. Answers

### Q1. Fallback command -- `.uno:CharLeftSel` only

1. **CL.** Constant-size read (561-581 bytes without a table), selects the paragraph break only, so the previous paragraph's characters -- and any as-char image or frame in them -- are outside the selection (cl-a4 vs sa-a4). The 037/038 hazard it still carries (a frame anchored at the dispatch paragraph wedging the html read) is the same one the primary SelectText read carries today on every paragraph; **not new to v28**, named as such.
2. **SelectAll rejected**, three reasons, each measured or read: (a) `LOK_SELTYPE_COMPLEX` above 10,000 plain-text characters (`init.cxx:6023`, 5/5) -- a verification that works only on short documents is a shape the user cannot predict and the product cannot explain; (b) a whole-document read reaches every image and footnote in the document, routing findings 037/038 into every last-line press on any document that has one, where today they are confined to the dispatch paragraph; (c) it buys nothing CL does not: wherever CL read NONE, SelectAll read NONE too (sa-a5/cl-a5, all five actions).
3. **"Both" rejected** for (c): no measured case where SelectAll would judge and CL would not. A second fallback is a second mechanism (CLAUDE.md §4) with zero measured yield.
4. **One claim the spec must not cite as measured:** CL's constant cost on a long document. README §4 says it was not run. One cell (`cl-long-300`, 5 rounds) before the spec pins "constant cost" as a reason (§5 below).
5. **Declared outside the measured set, fail-closed by construction** (to be stated, not silently skipped): an RTL last paragraph -- if Writer's Shift+Left moves logically forward there, forward at the document end is impossible and CL reads NONE -> the toast stays; **do not assert this in the spec**; either read `SwCursorShell::Left`/`LeftRight` in the link tree and pin it, or declare "RTL last paragraph: unmeasured; expected NONE (toast)". The caret in a table cell, frame or footnote whose last paragraph is empty (SelectText also returns NONE there, ruling 3 §2): CL may step into the previous cell (not TEXT, or a `<table>` -> refused) or to the previous paragraph of the same container (2 blocks, LAST = dispatch paragraph). Not measured; declared; optional cells if the owner wants them covered.

### Q2. The last-block field and the fallback route's rule

1. **Definition.** `lastBlockTag` = the last tag for which `formatTagIsBlock` is true in the scan (p, h1-h6, pre, blockquote); `lastListTag` = the innermost `ul`/`ol` still open at the moment that tag opens, `""` if none (predicate reads `""` as `none`, as the FIRST rule does). This is `read_q52.py`'s port, which was itself red-cased (nested lists, innermost wins; FIRST fooled where LAST is not; README "The parser port").
2. **Where.** Two fields in `FormatReadback` (`probe_engine.cpp:781-809`), computed in `parseFormatReadback` under the v28 define (an open-structural-tag stack beside `depth`; `malformedNesting` at depth 0 unchanged), serialized beside `listTag`/`blockTag` in `appendFormatBarrierDetails` on **every** record (cheap, and makes FIRST-vs-LAST visible in evidence on the primary route too). **Consulted only on the fallback route**, by a new `formatBarrierFallbackReadbackSatisfied()` that mirrors 5755-5768 with the two last fields. `formatBarrierReadbackSatisfied()` is not touched; SelectText readbacks keep v27's FIRST judgement.
3. **The fallback route's refusals, in order:** (i) fallback type not TEXT (NONE -> Q3.1; COMPLEX/other -> Q3.2); (ii) `!parsed`, `unknownTag`, `malformedNesting`, `footnoteApparatus` -- the existing set, which already refused every table cell; (iii) **`blockCount != 2`** -- new; (iv) `restoreConfirmed` false -> Q3.3; (v) the last-block predicate -> verified / `postcondition-not-met`.
4. **Why `blockCount == 2` and nothing about the first block.** From the start of an empty paragraph that SelectText could not extend (by source: empty, no adjacent next node), one position back crosses exactly one paragraph break, so the readback is the previous paragraph's tail plus the dispatch paragraph: two block tags. That is a per-instance property (CLAUDE.md §1 form one), measured on every non-table CL cell of all three runs (22 cells), and it is what the t1 cell violated when CL "went back into the table and covered the whole cell". One block means the caret was not where NONE implies; three or more means the selection took more than one position (merged paragraphs, hidden tracked deletions -- ruling 3 Q1.7's declared set). Both are unmeasured shapes; refusing them is fail-closed and lands in review (Q3.2), never in a wrong verdict. **No constraint on the first block** -- it is the previous paragraph's tail and is legitimately `p`, `h1`, or `li/p` (a8, n8); **no constraint on `itemCount`** (two list items are normal when both paragraphs are listed). `multiBlock` is not read on this route.
5. **The identity gate** stays as it is: declined by finding 074's clause on every core, because the dispatch paragraph is empty (§2 above). State it in the spec as a reasoned non-change, not an omission.
6. **The undo record** (v27 §4.1 item 4) is unchanged: before the dispatch, after the final restore; the fallback sits between them.

### Q3. Failure shapes and dispositions

1. **Fallback reads NONE** (blank document; anything that cannot move back). Terminal shape **stays `select-text-returned-none`**; the record gains `formatBarrier.fallback: {ran:true, command, selectionType:0, resultSeen}`. Reasons: the field's contract ("the synchronous read found LOK_SELTYPE_NONE") is true of both reads; the 083 sentence ("取不到任何內容") is exactly true; and the blank document is the owner's most-pressed case -- a renamed shape missing from `EMPTY_SELECTION_SHAPES` is finding 173 again, on hand test (b). The record, not the name, distinguishes "fallback ran and read NONE" from "no fallback" (finding 082's standard: a reader must be able to tell the cases apart). **No shell or page change for this outcome.** Keep the refusal `message` text unchanged too (checks may read it; the census says which).
2. **Fallback reads TEXT but the route refuses** (not TEXT/COMPLEX, `!parsed`, `unknownTag` e.g. table, `malformedNesting`, `footnoteApparatus`, `blockCount != 2`). **One new terminal shape, `fallback-readback-refused`**, with the sub-reason in `fallback.refusal` using the existing names (`unknown-structural-tag`, `footnote-apparatus-readback`, `malformed-readback-nesting`, `block-extraction-failed`, `selection-type-not-readable`) plus `unexpected-block-count`. The shape is honest per 1114-1118 (this is what ended the barrier). **The client must map it** (dispatched, collapsed, `selectionResultSeen`) **to `dispatched-unverified`** in the same shell generation (an exported constant beside `EMPTY_SELECTION_SHAPES`, with the same two-reader warning), otherwise 363-364 makes it a rollback -- harsher than today, forbidden. **The page needs a sentence for it**: neither existing sentence is true (083's says nothing was selected; 046's names multi-block as the cause). Default: one new short sentence, same shape as the other three ("動作已送出，但這一段是最後一段，檢查改用的第二次選取碰到表格或其他讀不了的內容，所以無法核對。請看一下結果，不是你要的就按「復原」。這是檢查的極限，不是文件壞了" -- wording is the main session's; the structure is fixed), chosen by the same `failureShape` field. If the owner declines new text, the 046 sentence is the fallback option and the spec must say it is approximate. This is text, not mechanism (CLAUDE.md §4 does not forbid it); finding 061 forbids the alternative.
3. **Restore not confirmed after a fallback that read TEXT and parsed.** Default: keep **`selection-not-restored`** and its existing disposition (rollback). This is the **one fallback outcome harsher than today's toast**, and I am ruling it deliberately: it is the same failure of the same barrier (the caret not put back after the barrier's own selection), which the primary route already treats as rollback; a route-local softer branch is the asymmetry ruling 3 Q1.2 rejected; natively it is 0/205 on exactly this restore (P3 in every round of every cell, all three runs); and today's path never *reports* it only because the NONE refusal comes first (§2). Conditions: the WASM acceptance cells (Q7) must show `restoreConfirmed:true` N/N in the engine record on both browsers before gen 82 freezes; the unit test covers "fallback + restore fails -> `selection-not-restored`". **Alternative B** (if the owner wants the constraint strictly): a named `fallback-restore-not-confirmed` mapped to review -- one more client list entry, one more red case. One line for the owner before pinning.
4. **Judged and not satisfied -> `postcondition-not-met` -> rollback.** This is not a violation of the constraint: the constraint is about the fallback's *inability to judge*; a judged failure is a document-state result, symmetric with the verified case (ruling 3 Q1.2), and the premise's confidence is the same in both directions (LAST = saved in every clean round; every sham not satisfied). Write this sentence into the spec so nobody later reads the rollback as a regression.
5. **Pre-dispatch refusals** unchanged (never reach the fallback). **The fallback's own UNO result**: expect it (so the ordered accounting stays clean -- the main session reads `expectOrderedUno`/`orderedUnoResult` to confirm what an unexpected result would do), record `fallback.resultSeen`, **do not gate on it**: it says `success:true` whether or not anything was selected (README §7) and carries no information.
6. **Worker projection** (model v27 §4.2): `fallback: {ran, selectionType, blockCount, lastListTag, lastBlockTag, refusal}`; not the html. Type-checked per field, `null` on a type mismatch, as the undo projection does.
