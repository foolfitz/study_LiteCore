## P1 — **relink 之前**，在出貨 artifact `835b453d…` 上

**這是承重的前置檢查**：Option C 的前提是「該修的機制早就出貨了」。
如果它在出貨 artifact 上根本沒有動作，或標錯，那個前提就垮了。

**預測**：對**同一個範圍**連續選兩次，第二次會在 **250 ms 上下**完成，
`completion` 是 **`verified-selection-readback`**。

| 觀察到的 | 判定 | 要做的事 |
|---|---|---|
| （A）約 250 ms ＋ `verified-selection-readback` | **預測成立**，機制在出貨 artifact 上活著 | 往下走，建組合 artifact。順帶把 039 那個「251 ms」假說結掉 |
| （B）走 callback 完成（`documented-callback-text-selection`） | core 對「沒變化」的選取**也會廣播** | **039 的模型要先修**，才可以 relink |
| （C）逾時／卡住 | **E1-D 出貨的機制不работает** | 新開 finding，**Option C 的前提失敗，停下來重議** |
| （D）第一次選取就失敗 | **什麼都沒量到** | 照實記，**不准事後解釋**；不得據此推論任何事 |

## P2 — 組合 artifact 上的第 8 臂類比

**預測**：**不重現**。格式動作 → 產品的範圍選取，會以兩條具名路徑之一完成，
**而且回報的選取要對得上請求的範圍**。

**判準是回報的狀態，不是「呼叫返回了」**（`probe_engine.cpp:1556`–`1559` 自己就這樣寫）。

| 觀察到的 | 判定 |
|---|---|
| 具名完成 ＋ 回報選取吻合 | **預測成立**，縮限 4 可以進入改寫程序 |
| 具名完成但**回報的選取不吻合**（空的、或別的範圍） | **功能性失敗**：縮限 4 **留著**，改寫成「會返回但沒選到」 |

## 撤縮限 4 的門檻（裁決訂的，寫在這裡免得事後放寬）

「憑重掃撤」具體指**以下全部**，在同一顆組合 artifact 上、兩個瀏覽器、**每一臂各開一顆引擎**
（finding 038 的教訓）：

1. A3／A4／A5 全矩陣以原尺寸通過，重新綁到新 hash。
2. **鑑別控制要先成立**：組合掃描工具必須**先在封存的 `c89f069e…` 上重現第 8 臂的逾時**，
   它在新 artifact 上的通過才算數。**一個在缺陷存在時也不會失敗的檢查證明不了任何事。**
3. 第 8 臂類比通過，判準見 P2。
4. **重複組合**：格式 → 選取 → 格式 → 選取，至少三輪，跨 A3 的三類 fixture（內文／標題／清單），
   不得出現 BUSY 卡死；每一臂之後再做一個瑣碎操作要成功，證明 `gEditorPending` 清掉了。
5. **v2 的主手勢**：格式 → `click`＋輪詢定位 → 再格式，至少三輪。
   （039 第 10／11 臂建立了 click＋輪詢可用，但**從來沒有在編進 barrier 的情況下量過**。）
6. **標籤分區**＝把判準做成可觀察的：刻意「不會有變化」的選取要走 readback 完成，
   會改變選取的要走 callback 完成，**harness 期限逾時必須為零**。

> **一併記下一個歸因缺口**：原生對照的五臂含 `format-then-reset`，**但沒有
> format-then-range**（039 那一節的表）。所以「core 是對的」對第 7 臂的形狀是量到的，
> 對第 8 臂的形狀**只是推論**。組合掃描直接量那一格。
