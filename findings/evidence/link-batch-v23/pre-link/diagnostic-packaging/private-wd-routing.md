# Bounded private W-D routing ruling

The owner delegated ambiguous v23 preparation decisions to Astra. During actual-source review, the root coordinator found that the preserved v22 manifest allows character moves only with `collapsed` gestures. The predeclared native W-D d4 sequence instead needs range Left after ShiftRight; d5 needs extended moves before delete-selection. The native landing oracle L uses ShiftEnd followed by ShiftHome before reading selection. Those inputs are not all exposed by the frozen public ABI 5 worker/gesture contract.

The build agent proposed a closed private diagnostic route, and the owner-proxy coordinator explicitly accepted it before any candidate WASM link or W-D execution. The coordinator subsequently requested the two native landing observer inputs for exact oracle parity. This is a route clarification for the existing criterion, not a public gesture expansion. The current native cohort records full specification hashes, so its running specification is not edited; the coordinator will append the ruling before the candidate WASM execution.

The sole `OXSDK_E2_V23_DIAGNOSTIC` entrance remains `int oxsdk_v23_diagnostic(int kind, int requestId)`. Its finite additional mapping is:

- 4: Left, requiring an existing document and an actual TEXT selection.
- 5: ShiftLeft, requiring an existing document.
- 6: ShiftRight, requiring an existing document.
- 7: ShiftEnd, requiring an existing document; native L landing observer.
- 8: ShiftHome, requiring an existing document; native L landing observer.

All five use the normal command queue, `dispatchOrderedKey`, and `composeOrderedEditorPending`. No arbitrary keycode, UNO command, new wire action, public capability, or public gesture mask is accepted. The public handler still consults the unchanged gesture gate before reaching that shared dispatch. Both private and public replies use the first post-command poll. The result measures candidate C topology with exactly the prescribed native input, and cannot establish an ABI 6 public feature. A feature successor needs its own identity and acceptance.

Kinds 1–3 retain their original diagnostic meaning. The private worker whitelist is exactly 1–8 and IDs are positive signed int32. The base SDK allocator remains uint32; this bounded private test entrance does not claim to cover its entire allocator domain.

Validation: `tests/test_ordered_engine_scope.py` preprocesses the actual v23 compilation command, checks the actual public gate before shared dispatch and private TEXT/document guards, and rejects causal mutations removing either guard. `tests/v23_diagnostic_worker_test.cjs` exercises the complete finite whitelist and rejects 9. No candidate WASM or browser execution is claimed here.
