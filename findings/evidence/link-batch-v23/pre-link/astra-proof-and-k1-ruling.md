The helper's three outcomes are appropriate for the editing-operation proof decision: dispatch failure takes precedence, present proof is available for the caller's semantic validation, and absent proof after dispatch produces `MUTATION_OUTCOME_UNKNOWN`. There is no pending/deadline outcome. The test exercises the production pure poll helper, both missing-proof branches, error codes and stale-proof precedence.

The corrected flush test sets result proof present **before** cursor and selection callbacks, and explicitly requires that neither callback emits a reply. This isolates rule 5: the old callback composer fails because it emits too early with partial state, not merely because result proof was absent. `ordered-reply-02.txt` records the corrected test and refusal mutations. This establishes a pure helper/model property only. It does not establish that actual engine callbacks refrain from composing replies, that actual dispatch creates a pending reply for every path, that proof attribution uses the correct command/sequence, or that the first real post-command poll performs the decision. Wiring must still emit `failureShape: proof-absent-at-poll:<callback>` and preserve the existing non-retry SDK search/annotation error contracts. `Available` means proof exists, not automatic semantic success. In particular, a format's `success:false` result must retain the measured 059 state-validation exception; it must not be indiscriminately relabeled as a no-mutation dispatch failure.

**K1 decision:** preserve the existing **4096-byte** maximum for the separator/merge input, explicitly registered as the headless diagnostic's supported-input bound. This retains the refusal already present in v22 `verifyAndDispatchSelectionBarrierDelete`; it does not justify new staging, timeouts or another native/browser cohort. NONE routes to the specified boundary noop. TEXT must be present, nonempty, valid UTF-8 and no larger than 4096 bytes. Classify separators before applying the smaller **128-byte** bound: a supported separator routes to the measured restore/key branch; a nonseparator safe text unit must additionally fit 128 bytes. Oversized or unsupported input is a typed unsupported refusal and never falls through to Delete or an unconditional key.

Append the clarification to the specification without editing section 16.2. Include separator inputs at 129, 4096 and 4097 bytes in the already required synthetic K1 classification cases. These are classifier boundary controls, not a new acceptance population. The engine RESET branch remains prohibited until the fixed native RESET measurement establishes it; this ruling and pure classifier tests do not substitute for that measurement.
