## 1. 裁決（白話，給擁有者）

五題，加上對主 session 處置表的意見。先講最重要的一題。

**第一題：游標處的刪除，拿什麼證明「真的刪了」。復原紀錄一個人不夠，實量已經證明。**主 session 在原生量到：連按 Backspace 或 Delete 穿過 30 個底線，第 20 下起 `.uno:Undo` 的內容跟前一下一個位元組都不差，但每一下都真的刪掉一個字（存檔是 `Name: _____`）。原因是 Writer 自己的行為：連續刪同一類字元會合併成**一筆**復原，而那筆的說明文字到第 19 個字就截短成「________..._______」，之後再刪長得都一樣。這不是罕見路徑：**中文沒有空格，一句二十幾個字很平常**；按住 Backspace 刪一句，第 20 下起規格現在的寫法會回答「什麼都沒發生」——Delete 那一邊游標不動、選取不動、復原不動，三個條件全成立，頁面照單全收、版本號停住、也不標髒；Backspace 那一邊則掉進規格沒寫到的縫。

裁決：

- **證人換成兩個一起看**：復原紀錄，加上引擎本來就有的同步讀法——焦點段落的文字跟游標位置（`getA11yFocusedParagraph`）。規則是：復原變了→刪了；復原沒變、但**游標原本在段落中間**而段落文字變了→也是刪了（它合併進既有的那筆復原，`actionsAfter ≥ 1` 仍然是真的，凍結的頁面照收）；兩者都沒變→沒有作用。段首、段尾只看復原，因為那裡 Writer 可能只移游標或原地不動而不改文件（表格邊界就是）。「游標沒變」從判準裡拿掉——它沒有同步來源，也不是頁面要的；頁面要的是「文件變沒變」，游標照 §5.2 從 flush 之後的快取**回報**就好。
- **不關掉合併**（那會把使用者按一次 Ctrl+Z 的顆粒度改掉，而「照 Writer」是這整批的性質）。**不回去用柵欄**（編號／縮排那個洞就是柵欄挖的）。
- **這個讀法「返回時就已經是新的」目前只是讀原始碼的推論**（Writer 在每次動作結束時同步發 a11y 事件，LOK 的監聽器當場更新）。先在原生量：g1／g2 兩支臂加上 a11y 讀取，N=5，再加三個對照：20 個以上的中文字、表格後面那一段的段首 Backspace（Writer 會原地不動）、文件末端的 Delete。這支臂同時就是紅案：只看復原的判法在第 20–25 下會判錯。**沒量之前不寫 §5.4 的引擎碼。**
- **量不出來的預設**：游標刪除維持今天的柵欄路徑（C 之下它也是同步的，由 `.uno:Delete` 的結果判），L-C-number-or-indent **重新登錄為未關閉**。附錄 §2.2 撤柵欄的那句，前提是「復原證明夠用」，前提已經倒了，所以改成有條件的，原文留著。

**「意思」怎麼測，不只測字串**：三層。原生——存檔少了幾個字，引擎就得說「刪了」幾次（25 對 25；只看復原的判法會說 19）；引擎單元測試——把那次量測錄下的每一下輸入當 fixture，標籤由存檔推出來，不由判法自己說；產品路徑——用真鍵盤打 25 下 Backspace 刪一句中文，頁面版本號每下 +1。模型那邊：它的「對不對」是自己告訴自己的（opus 證明 174,672 筆標錯照樣 `ok`），**撤回**「偽造完成那一類為空」當成對回覆的宣稱；模型不加新模式。

**第二題：收合游標上的粗體。**「`STATE_CHANGED` 是計時器類」這句**撤回**（是我在附錄裡寫的，N1 自己的資料推翻它）：Bold 的狀態 5/5 在指令自己的 flush 裡就到了，表格、剪貼簿那些才晚到——是**逐項**的，不是整類的。Writer 對收合游標的粗體回 `success:false`，但它真的套了（下一個字會是粗體），今天引擎靠 059 那個檢查救回來，C 之下照留：回覆讀 flush 裡的 Bold 狀態，而且**只准讀 N1 量到準時的那幾項**——清單由 N1 的判讀工具從紀錄裡生出來，引擎的表用單元測試去對。四個行內格式的狀態項加進 N1a 的「回覆依賴的回呼」，**下一次 N1 重跑**才算，這次的不算（判準不能在已經滿足它的執行之後才加）。

## 2. Answers (English)

### 2.1 Q1 — The at-return proof for a caret delete: undo payload paired with the focused-paragraph read, guarded; measured before relied on

**What the measurement shows (re-read).** `disposition-1/grouping/reader-output.txt`: under `uni1`, g1 (25 × Backspace) and g2 (25 × Delete) through `Name: ` + 30 `_` return a byte-identical `.uno:Undo` payload at ops 20–25 (6 of 25) while every op deleted a character (saved `Name: _____`, 4/4 cells); `seq` shows the same from op 21 (its op-1 read precedes the posted key: `actions 0`). The mechanism is Writer's: a single-character delete merges into the last `SwUndoDelete` when `DoesGroupUndo()` and `CanGrouping()` hold (`lo/sw/source/core/doc/DocumentContentOperationsManager.cxx:4648-4666`; conditions: same node, adjacent index, same direction, same `isLetterNumeric` class, no fly selected — `lo/sw/source/core/undo/undel.cxx:536-580`). The comment is `ShortenString(aStr, nUndoStringLength = 20, "...")` (`undel.cxx:842`; `lo/sw/source/core/inc/UndoCore.hxx:247`; `lo/sw/inc/strings.hrc:542`; `lo/sw/source/core/undo/undobj.cxx:1626-1643`), applied to the already-quoted string, so saturation begins at 19 deleted characters — ops 19 and 20 both read `Delete “________..._______”` (raw JSON of `g1-uni1.jsonl` checked) — which is why the first unchanged read is op 20 and not the seat's predicted 22. The payload carries `index`, `comment`, `viewId`, `dateTime` only (`lo/svl/source/undo/undo.cxx:1309-1318`), none of which grouping changes. `judgeAfterKey` returns undecided on an unchanged payload (`R/wasm_sdk_probe/src/merge_key_undo.hpp:399-404`), and the spec then answers `verified-boundary-noop` (§5.4 `:124`, §5.5 `:131`), which the frozen client accepts with `changed:false` and the revision unchanged (`client:372-374`) — for a key that deleted a character. The user-facing path is real: CJK text has no spaces, so a 20-character same-class run is one ordinary clause, and key auto-repeat is exactly "one direction, one paragraph".

**Ruling.**

1. **(b) is refused.** Turning grouping off for the engine's keys changes what one Ctrl+Z undoes for the user; this batch's property is "as Writer". It is also a mechanism built to keep a claim true (CLAUDE.md §4).
2. **(c) is refused.** The barrier at positions (i)–(iii) *is* L-C-number-or-indent; readmitting it for mid-text deletes needs the engine to know the position, which is the hole.
3. **(a) is adopted, with this read and this guard.** Beside the `.uno:Undo` payload the engine reads `getA11yFocusedParagraph` (`lo/desktop/source/lib/init.cxx:4092-4110` → `SfxViewShell::getA11yFocusedParagraph` → the listener's `content`, `position`, `start`, `end`, `lo/sfx2/source/view/viewsh.cxx:862-871`, `:884-888`) **before the key and at return**, in the same poll with no yield between (§5.7 rule 1). The engine already has this read (`pe:1953-1967`, `readEditorSemanticSnapshot`) and already enables a11y on its view (`pe:2200-2210`). Decision rule:
   - undo payload differs ∧ the after-payload parses to ≥ 1 action → `verified-key-undo` (as §5.4);
   - undo unchanged ∧ **the before-read's caret was strictly inside the paragraph** (Backspace: `position ≥ 1`; Delete: `position < content.length`) ∧ `content` differs → `verified-key-undo`, `changed:true`, revision +1, `keyUndo.actionsAfter` = the after-payload's action count (≥ 1, because the merged action exists — the client's structural check `client:161-166` is satisfied and literally true: the deletion is in the undo stack, merged);
   - otherwise → `verified-boundary-noop`, `changed:false`, revision unchanged.
   The guard is what makes the content read sound. At a paragraph start Writer's `DelLeft` either joins (a new `SwUndoDelete`; grouping never spans nodes, `undel.cxx:537-545`) or, when the probe crossed a table or cell boundary, restores the caret and does nothing (`lo/sw/source/uibase/wrtsh/delete.cxx:198-237`, tdf#115132); so at `position 0` only the undo decides, and a caret that moved without a document change is reported, never judged. Mid-paragraph, a caret delete removes one character (content differs) or does nothing (content same); a field or an anchored fly is never grouped (`undel.cxx:566-580`), so it is undo-visible.
4. **§5.5's "caret and selection unchanged at return" is struck as a condition.** Opus is right that it has no synchronous source (the caret cache is refreshed only by the flush, `R/handoff/link-batch-v23/facts-async-key-machinery.md:36-40`), and it is not needed: the client's no-op tuple is about the document (`client:363-374`). The reply's `state` is the post-flush cache, which §5.2 guarantees is this command's flush.
5. **The read's synchrony at return is by source only and must be measured.** By source: the key's `EndAction` runs `SwViewShell::ImplEndAction`, whose last act is `Imp()->FireAccessibleEvents()` (`lo/sw/source/core/view/viewsh.cxx:456-459`; `viewimp.cxx:522-526`), and the LOK listener updates `m_sFocusedParagraph`/`m_nCaretPosition` inside `notifyEvent` for `CARET_CHANGED` (`lo/sfx2/source/view/viewsh.cxx:1475-1507`, `:1490`) and `TEXT_CHANGED` (`:1512-1533` → `updateParagraphInfo` `:1176-1207`). So at `postKeyEvent`'s return the cache should be the key's. Finding 016 found it lagging under the threaded topology, where the key had not yet run (`pe:1950-1953`); that cause is gone under C. **Not relied on until measured** (CLAUDE.md §7): re-run g1/g2 with `setAccessibilityState(true)` in the harness and the a11y read beside `undoValues()` at return, `uni1` and `seq`, **N = 5** (the committed grouping run is one round per cell), with three controls: a 25-character CJK run (the user's path); Backspace at the start of the paragraph after a table (Writer restores: must read noop, undo and content unchanged); Delete at the document end (noop). **The arm is its own red case:** the undo-only decider must label ops 20–25 noop; the paired decider must label all 25 deleted.
6. **Form:** form 1 over every caret-delete op of every arm — the reply's class equals the saved-document oracle (below). **Default if the measurement is never made or fails:** §5.4 is not implemented; caret deletes stay on today's barrier path (select the character, `.uno:Delete` with a listener → `UNO_COMMAND_RESULT`, synchronous under C, completion `verified-selection-delete` via `uno-command-result`); **L-C-number-or-indent is re-registered as open** (§4 row 13 → re-registered); addendum §2.2's barrier withdrawal is corrected to "conditional on 2.1 item 5", appended, the original kept.

**How the meaning of a completion is tested, not only its string.** The decider's inputs are recorded; the oracle is independent of the decider.

- **Native (form 1 per cell):** the number of ops the decider labels `deleted` equals the number of characters the saved document lost (g1/g2: 25 = 25; the undo-only decider gives 19). The noop controls must count 0.
- **Engine unit test (form 2, tool-closed):** the decider is a pure function of (undo before/after, a11y before/after, key); the recorded tuples of the native run are committed as its fixture, labels derived from the saved text; the red case feeds the undo-only variant and must mislabel 6 ops.
- **Product path (§9.3, form 1 per press; CLAUDE.md §9's four conditions — written now, forced and named by `disposition-1/grouping/README.md`, closed at v23's first clean count run):** CDP types 25 Backspaces through a 25-character CJK run; the page's revision advances by exactly 1 per press, the saved text matches, `dirty` is true after the first press.
- **The model cannot test meaning.** Its completion comes from its own `keyChanged` oracle (opus Q9 `model:651`, `:672-693`; E6 mislabels 174,672 deletions and the committed test still ends `ok`, `E6_lying_noop.summary.txt`, `make_e6.py`). §14's "0 forged" is **corrected** to "no reply's selection or caret rectangle differs from core's" (both seats; the main session agrees). No new model mode (CLAUDE.md §4).

### 2.2 Q2 — The inline format at a collapsed caret: the type-level claim is withdrawn; the reply reads the on-time state item; the on-time list is tool-generated

- **Withdrawn:** "`STATE_CHANGED` is timer class" (spec §5.2 `:98`, §5.3 A7 `:112`, §11 `:223`; addendum §2.3 — mine). N1's own records refute it: `.uno:Bold=true` and `.uno:ModifiedStatus=true` arrive in the Bold op's own flush, 5/5 (`opus-experiments-1/native/a9_bold_state.out`). This is established **by index**: the op's `lateCallbacks` (callbacks at index ≥ `cbIndexAtFirstPoll`, `oc/tool/oc_native.cpp:485-488`, `:494-496`) contain no Bold item. The printed "ms after return" (0.15–0.18) exceed `firstPollAfterReturn` (0.07–0.09) because `firstPollAfterReturnMs` is measured from `opReturnedMs`, stamped after the at-return reads (`oc_native.cpp:303-305`, `:479`): the time columns are relative to an early estimate and do not by themselves establish the order; the index does (the main session's brief and the seat state the right fact; this is the reason it holds). The split is per item (`a10_state_split.out`): on time `.uno:ModifiedStatus` 50, `.uno:Bold` 5, `.uno:StateWordCount` 5; late the table and clipboard states (50/10/10 each) and `.uno:Undo`, `.uno:DocumentRepair`, `.uno:StateWordCount` mostly late and occasionally on time.
- **What the reply reads.** Writer answers `.uno:Bold` at a collapsed caret with `success:false` in seq and unipoll alike (opus A8; the engine's own comment: "`success` is not evidence about the document", `pe:2827-2831`). The html readbacks are selection reads and give nothing at a collapsed caret (opus, `pe:4851`, `:4885`, `:4948`). The honest witness is the `.uno:Bold` state item of **this command's flush**, which the cache holds at the reply poll because §5.2 orders the flush before that poll. **059's check stays** (`inlineFormatArgumentResolved`, `pe:2120-2131`: `boldKnown && bold == requested`); `success` is not used as the truth for the four inline formats.
- **Rule (replaces the type-level clause).** A reply may read a `STATE_CHANGED` item only if `(command kind, state key)` is in the **on-time list**: the set N1 recorded before the first poll in every round. **Form 2:** `read_n1.py` generates the list from the records (a10 is the prototype); an engine unit test compares the engine's table of read keys against it; a key read by the engine and absent from the list is red. L-timer-class-callbacks is reworded to name the late list, also tool-generated.
- **N1a's reply-dependent set gains the four inline-format state items** for format commands (Bold measured; Italic, Underline, Strikeout to be measured — the d4 variants are added to the N1 arms). **Prior to satisfaction:** this applies to the **next** N1 run, not the committed one (CLAUDE.md §9 condition 1).
- **Default if never re-run:** no format reply under C does more than today's engine does (059's check on the cache); the on-time list is Bold only, from a9, registered as a one-time measurement (form 3, not a criterion).

### 2.3 Q3 — An object click: the limit is Writer's own 120 ms; the reference is the settled Writer; the click's completion does not wait; a named limit with a §9.3 arm

- **Re-read.** `MouseButtonDown` sets `g_bNoInterrupt = true` (`lo/sw/source/uibase/docvw/edtwin.cxx:3289`) and the frame-select branch returns with it set (`:3874-3880`). `SwView::AttrChangedNotify` then defers: `m_bAttrChgNotified = true; m_aTimer.Start()` (`lo/sw/source/uibase/uiview/view.cxx:567-574`; 120 ms, `:844`), and every later notify is skipped while `m_bAttrChgNotified` holds (`:567`). `TimeoutHdl` runs `SelectShell()` with undo off and `NotifySelChanged` (`:600-622`). `MouseButtonUp` clears `g_bNoInterrupt` (`:4840`, `:4930`) but not the deferral. The only `StopShellTimer()` caller in `edtwin.cxx` is `Command` — the context menu (`:5841-5850`; `view.cxx:1918-1931`); `KeyInput` (`:1392`) has none. So **keys are not exempt**: a key or a `.uno:` within 120 ms resolves on the pre-click stack. Slots differ per shell: `FN_BACKSPACE`/`SID_DELETE` in `SwBaseShell` (`lo/sw/source/uibase/shells/basesh.cxx:258-299` → `DelLeft`, which takes the object path when a fly is selected, `delete.cxx:139-162`) and in `SwDrawBaseShell` (`drwbassh.cxx:389-402`); `.uno:Bold` exists on the text stack and not on the frame or draw stack.
- **Which Writer: the settled one.** Spec §3 defines the reference as seq ("每個指令穩定後才送下一個＝實量的 Writer 順序", `:46`). The 120 ms race exists on the desktop too, but no human dispatches a UNO command 20 ms after a click; the engine does.
