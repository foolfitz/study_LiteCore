# Actual-source disposition: first-poll engine review

The review is advisory and did not approve a link. This disposition checks its claims against the complete source and SPEC-M3 ordered commands through append 18. No candidate WASM execution is claimed. The original review and source snapshot remain preserved.

1. **Accepted and fixed.** Recording every callback could attach an unrelated newer sequence to a malformed cursor/selection payload. `recordParsedCallback` now records only successfully parsed editor-state callbacks (`editorStateChanged`). The host test sends an accepted event at sequence 5 followed by a malformed different event at sequence 6: the latter must not become proof. A mutation accepting the malformed payload fails. The actual-preprocessed engine test also rejects bypassing the parse argument.
2. **Rejected as a blanket change.** Section 16.4 explicitly permits movement/caret/selection without a matching callback to reply with `verified-*-readback`. The composer reads the live post-flush editor cache through `appendEditorState`, distinguishes the no-callback completion, and reports `changed:false` for moves. It does not claim a documented callback when none matched. There is no LOK call inside the poll composer by design. Item 1 separately fixes forged documented-callback claims. Missing required UNO/search/comment proof is still refused at that poll.
3. **False against the full source; protection tested.** `updateEditorFormatState` records recognized, successfully parsed state keys in `gOrderedProof.stateItems`, gated to the active command/reply. `inlineFormatArgumentResolved` requires the command's own key before consulting the live cache. Per-dispatch/reset lifetime prevents borrowing an earlier command's key. The actual-preprocessed test now rejects removing the insertion or bypassing the lookup. V23 requires v21's transitive format-barrier define through compile-time errors; the hypothetical no-barrier V23 is invalid. Native FORMAT restoration is a separate gate, now formally passed, and does not replace this source proof.
4. **False premise / preserved refusal policy.** `startUnoMutation` registers the UNO expectation, installs its owned reply, posts the requested UNO, then posts `.uno:Escape` when operation is `comment-added`. The callback no longer calls LOK. Section 16.4 explicitly retains existing non-retry SDK-operation codes; absent COMMENT produces `LOK_ERROR` with explicit missing-proof shape. It does not assert that no mutation occurred.
5. **Not reproduced.** Actual call sites register expectations before `postUnoCommand`, including the FORMAT and DELETE includes. `expectOrderedUno` uses `emplace`, so a repeated expectation cannot erase a seen result. Callback delivery records the matching result payload; the review's reversed registration is conditional and absent from this source. No alternative duplicate-result protocol is invented.
6. **Accepted cleanup defect and fixed.** Normal dispatch exceptions were already caught by `executeQueuedCommand`, and `runOnePoll` already had RAII. However, exceptions in that error handling could strand `gOrderedDispatching`, and the outer `mainLoopPollCallback` flag lacked RAII. The dispatch, composition, and outer callback now use `FlagScope`. Executable tests throw while nested poll/dispatch flags are set and while composing; all reset. The destructor-removal mutation fails, and integration mutations removing actual call-site guards fail. This is cleanup protection, not a claim that allocation failure can always serialize a recovery message.
7. **Engine-thread ownership clarified.** The mutex protects the queue shared with submitters. Reply/proof slots are engine-thread-owned; poll, anyInput, dispatch, and LOK flush callbacks execute there in candidate C. Private kind 3 deliberately performs the off-thread negative-control LOK call after rejecting queued/executing/asynchronous work. The adapter comment now states ownership. There is no demonstrated cross-thread reply-slot writer.
8. **Not reproduced.** JSON construction and `appendEditorState` happen before `emitJson`; a failure there has not delivered a terminal reply. The proposed ordering in the finding is not the actual code. `finishAsynchronous` itself immediately returns for ID 0. No speculative second terminal protocol is added.
9. **Checked.** Deferred handlers capture commands and readback values by value (`[command]`, `[=]`, or named owned values), not by reference. `closeDocument` copies its optional command before deferral. `gOrderedCommand` also owns the current command through reply. No dangling dispatch-local command was found.
10. **False route.** The public caret-delete handler rejects the old manual bypass option before calling `startOrderedCaretDelete`. Native Q does not authorize or claim that rejected bypass. DELETE Q authorizes only the measured separator restoration, with both ordinary unit and separator paths retaining their own completion fields.
11. **Intentional retirement.** Section 16 replaces old asynchronous merge attribution/staging with return-time Pstart/P0/Pafter and a first-poll composer. No new delete path calls `feedMergeAttribution` or old staged merge helpers. The actual-preprocessed test rejects legacy roots; the old Writer/Calc preprocessing is separately unchanged.
12. **Not reproduced for a reachable normal path.** Movement/select/caret install a reply when they establish pending operation state. Dispatch failure replaces any installed reply with a deferred typed error; the first-poll adapter clears `gEditorPending` after reply. Rejected preconditions occur before installing pending state. Catastrophic allocation/error-serialization failure is not asserted to be recoverable; item 6 ensures scoped flags unwind.
