# Packaging resume review disposition

The review was checked against the complete wrapper, resume tool, pre-link source inventory, and successful packaging receipt. It did not find a defect in the frozen candidate bytes. All fixes below affect Python packaging tools/tests only. No engine/SDK tail/Makefile flags, candidate files, archived files, or successful receipt were changed. Packaging and building were not rerun.

1. **Accepted.** The old guard rejected an existing manifest/derived worker but allowed another partial profile directory to be overwritten. The resume tool now rejects a nonempty existing output directory before any pack check or write. Empty directories remain harmless. Failures quarantine the whole newly created profile under an exclusive failure directory name, retaining loader/WASM/worker as well as any manifest. A fixture containing an old partial WASM is rejected without launching checks or overwriting its bytes. Removing the nonempty-directory condition makes this test fail.
2. **Accepted.** The wrapper's cleanup removed the manifest target, preventing false make success, but lost the exact rejected bytes. It now moves those bytes to a uniquely allocated `sdk-manifest.failed-*.json` inside the output directory. That directory is subsequently quarantined by the resume tool if it is the caller. The wrapper still removes the success target and preserves captured stdout diagnostics. A parse-failure fixture verifies the precise rejected bytes; reverting to unlink makes the test fail. No old failed or successful manifest is overwritten.
3. **Accepted.** The protected-input verification after `package()` returned was outside its quarantine boundary. The verification now runs after all packaged hashes are read and before the package transaction returns, inside the same exception handler. A mutation of an audited object during an otherwise successful fixture pack causes the complete new profile and derived build worker to be quarantined. The CLI no longer performs a second successful-package verification outside that boundary; check-only and failed transactions retain their verification reporting. Reverting the in-transaction check makes the causal test fail.
4. **Not reproduced; already bound.** Both inputs are in the original pre-link `source-inputs.json` and neither is in `PACKAGING_DELTAS`: diagnostic tail SHA-256 `60132c57f275bf7d7eb69242520a7222c1af6e6ae0c51d60ae53946ddcb4ff0a`, source manifest SHA-256 `06d1ed955f3518d5a34ff592593596690dd0831a4de5b80e218f6f8fcb310ac2`. `validate()` verifies those actual files. The wrapper additionally compares the supplied worker bytes against the checked frozen base concatenated with the actual tail, then verifies the final manifest's worker/loader/WASM bindings. An extra derived-worker hash predicate would duplicate this exact-byte comparison.

**Rename-error remark accepted.** Cleanup now attempts each quarantine operation independently, adds failures as notes to the original exception, and continues processing remaining files. The original packing failure is retained. An injected directory-rename denial verifies both primary-error preservation and subsequent worker quarantine; reverting to raising the cleanup error fails. A filesystem that refuses a rename can still prevent that particular isolation; this is explicitly reported rather than represented as successful cleanup. No new retry mechanism is introduced.

**Default-root remark checked.** The production `validate` and `verify_rows` defaults were the same module `ROOT`; the original CLI did not have a differing-root path. The edited package and CLI verification calls pass `ROOT` explicitly, also making fixture-root tests unambiguous. This was not a production namespace mismatch.

Verification: 10 resume test groups, 20 wrapper test groups, and four in-memory causal reversions all pass their expected outcomes. The reversions compile Python modules in memory and run the actual focused regression cases; they neither mutate repository modules nor execute packaging against product directories. `cleanup-fix-preservation.json` verifies candidate and archive hashes against the successful receipt, plus all five archive checksums. These tool fixes do not mint a new candidate identity and do not authorize another packaging or build attempt.
