# Private r2 HTML diagnostic review

The first request was captured while the helper extraction was underway and omitted the extracted helper body. Its conditional findings were checked against complete committed source, then a second request supplied the full helper and actual protocol context. The second completed review found no concrete defect in the supplied new kind9 code. Neither review is browser acceptance.

1. Malformed-result JSON: `jsonEscape` escapes every ASCII control byte, quotes and backslashes. No reproducing malformed HTML event was identified. The diagnostic remains fail-closed on malformed wire data rather than treating it as a successful transfer.
2. UTF8 byte count: LOK returns a NUL-terminated UTF8 string. The owned string and event count use that same string; the worker independently checks UTF8 length. Invalid encoding is rejected as WORKER_PROTOCOL_ERROR, not accepted as successful evidence. A new base64 transport or mismatch-as-success mechanism is unwarranted.
3. Null versus empty: both can report an empty returned value, but the independent040 reader requires nonempty HTML containing the selected image and anchor. Neither can satisfy that criterion. The operation reports what the literal call returned; it does not by itself assert a valid selected-frame witness.
4. Pending registration: actual frozen base `accept` installs the request operation and payload before invoking the C entrance. The alleged inverse ordering is absent.
5. Orphan diagnostic HTML: this private profile deliberately preserves actual return events as diagnostic evidence, including a result without a matching pending request. No public method is added. An orphan cannot complete another operation or satisfy the independently attributed040 reader.
6. Composer overwrite: the poll prioritizes an existing reply before draining another command; `setOrderedReply` additionally throws if a second reply is installed. Existing two-browser contention evidence covers the original same queue/poll path. A worker-side rejection layer would change that measured protocol without a demonstrated bug.
7. Request identity: the private operation acts on the current validated document and accepts only kind, not a caller document/MIME/key. The bridge matches the exactr2 profile, ABI5, pending operation, request ID and pending kind9. Both entry and return evidence are independently matched by the040 reader. A mandatory caller document field is not part of this closed entrance.
8. Liveness: kind2 actual original-candidate cohort passed in both browsers N3. Newkind9 fake-LOK tests verify deferred captured reply with no LOK in composition; actualr2 remains unlinked and its positive browser test remains NOT_ESTABLISHED.
9. Override binding: the base initialization assigns `self.__probe_on_event = handleCEvent` when a later initialization request runs, after the concatenated tail has evaluated. Actualbase VM tests cover the derived bridge; no const reassignment or premature callback capture was found.

The coordinator read the complete helper, engine dispatch/C entrance, base pending setup, JSON escaper and ordered reply guard. The new helper makes the literal call during dispatch, owns/free's the returned allocation, emits its return, and captures only owned HTML for the next-poll response. Existing public037 guards and frozen candidate bytes remain unchanged. Focused tests and causal controls are recorded by the build agent; no compiler/link or browser run is claimed by this review.
