Each row identifies nativeArmId, browser, profile, fixtureSha256 and the actual document generation. Preserve raw posted requests as `{generation, requestId, operation, payload, at}`, raw terminal replies with the same key and result/error, actual client replies, all relevant editor-state/cursor events, and actual page user agent. Request identity is the pair `(generation, requestId)`; a reused integer in a fresh worker is not the same request. S2 stores full `replyState`, `replyAt`, and delayed `readback`/`activeSelection` records bound to their actual wire pairs. Capture the rest of the full states without treating ordinary source-sequence advancement as a cursor mismatch. Moves retain unchanged revision and changed:false. Record cursor events after readback through the actual document-close reply; absence in that bounded interval is not a claim about arbitrary future events. No extra wait, callback deadline or recovery is introduced.

## S5 exact continuation families and oracle availability

For every Table 1 Shift key, replay exactly these seven families, without waiting for the predecessor promise before dispatching the following product input:

1. Shift+key → Backspace.
2. Shift+key → Delete.
3. Shift+key → type literal `x`.
4. Shift+key → Backspace → Backspace.
5. Shift+key → Delete → Delete.
6. Backspace → Shift+key → Backspace.
7. Delete → Shift+key → Delete.

The final two families include the trailing deletion: original ruling-3 Q4's Sequence A was Backspace, ShiftLeft, Backspace. They are not truncated to delete→Shift. This is 84×7=588, with no new family. One native execution of the exact continuation and its actual before/after saved documents must be identified for each cell requiring a native oracle. The archived signature tool only took snapshots after single moves and interactions; it did not save these continuation results. The generated table therefore marks required native continuations `NOT_ESTABLISHED_MISSING_EXECUTION`, lists their required artifacts and cites old snapshots only as setup evidence. Left/Right account for 196 mandatory native-reference cells; Up/Down account for 196 mandatory settled-WASM-reference cells; 196 Home/End cells choose native only with the actual single-line witness, otherwise settled WASM. These are reference partitions of the same 588 cells, not added feature cases. No new native continuation generator or executed oracle is claimed by this preparation.

Deletion-bearing families compare content.xml after the existing §24 `run_merge_wasm_shakedown.reduce_content` reduction: sort root namespace declarations, remove empty office:forms, remove text:soft-page-break. No other XML/style normalization is authorized here. The type-x family compares the existing paragraph text sequence from `odt_paragraphs.paragraph_texts_from_xml`, preserving the established treatment of spans, spaces, tabs and line breaks. The table pins both source files. Native no-effect outcomes at a boundary remain valid only when an actual oracle demonstrates them; missing effects may not be guessed.

For layout-dependent cells, the oracle is a **fresh same-cell WASM arm with a settled wait before the follow-up**, exactly as `findings/evidence/link-batch/review/ruling-3.md:55` prescribes. Wait for the Shift terminal and obtain the §10.2 actual engine-state/active-selection witness at least 500 ms later before sending the continuation. The timed candidate receives no inserted wait. The separate reference save is the oracle; the timed candidate's final save cannot serve both roles. Prefix-delete families retain the same prefix-delete→Shift sequence; doubled-delete families retain both follow-up keys. The reference introduces the declared settled observation at the Shift/follow-up boundary, not an arbitrary wait before every key. Missing native save where required, missing fresh settled arm, missing setup or missing single-line evidence for a claimed native Home/End comparison leaves the cell NOT_ESTABLISHED.
