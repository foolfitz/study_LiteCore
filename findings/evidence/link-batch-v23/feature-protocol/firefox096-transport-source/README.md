# Firefox096 instrument source preparation

This unit prepares the dedicated RDP worker-error transport authorized in `handoff/WORKORDER-2026-10-26-v23-product-four-arms.md`. It does not establish an actual Firefox error, B2, B4, product recovery, or any product-arm result.

The new `wasm_sdk_probe/tools/firefox_worker_error.py` implements one sequential actor traversal, with the existing inducer's four-second transport budget. It matches the exact owned page and bound document-worker URLs, obtains the worker's actual console actor, schedules the existing uncaught `setTimeout` error, and correlates `evaluationResult` with its acknowledgement by actor and resultID. Events arriving before acknowledgements are preserved. Only the loopback endpoint of a new owned Firefox instance is contacted. A refusal, ambiguous target, absent result or unsupported installed protocol returns `fired:false` with raw packets; it never becomes a recovery success.

`primary-source-pins.json` binds the primary Mozilla implementation to commit **efd2d1e6f77570ae6bc5294731a68101e45c81a3**, with immutable raw URLs and SHA256 for six files. The source chain is [`DevToolsStartup.sys.mjs`](https://github.com/mozilla-firefox/firefox/blob/efd2d1e6f77570ae6bc5294731a68101e45c81a3/devtools/startup/DevToolsStartup.sys.mjs), [window target `listWorkers`](https://github.com/mozilla-firefox/firefox/blob/efd2d1e6f77570ae6bc5294731a68101e45c81a3/devtools/shared/specs/targets/window-global.js), [worker descriptor `getTarget`](https://github.com/mozilla-firefox/firefox/blob/efd2d1e6f77570ae6bc5294731a68101e45c81a3/devtools/server/actors/descriptors/worker.js), and [console `evaluateJSAsync`](https://github.com/mozilla-firefox/firefox/blob/efd2d1e6f77570ae6bc5294731a68101e45c81a3/devtools/shared/specs/webconsole.js). These source pins describe the proposed transport; they are not a claim that the locally installed Firefox is built from this revision. BiDi was not selected: its worker evaluation implementation remains tracked separately in [Mozilla1936776](https://bugzilla.mozilla.org/show_bug.cgi?id=1936776).

The recorded mock run is `preparation.json` plus `mock-tests.stdout` and `mock-tests.stderr`: four test methods pass, including fifteen altered-packet controls, both event/acknowledgement orders, fragmented length-prefixed packets, exact command targets/expression, socket cleanup and owned-loopback launch options. These are finite instrument controls, not additional browser cases or product thresholds.
