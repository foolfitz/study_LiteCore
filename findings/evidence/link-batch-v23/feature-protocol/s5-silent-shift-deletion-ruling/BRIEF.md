## What happened

1. **Counted run stopped.** `../s5-counted-01/` (HEAD `1e63f8de`, launched 07:31, Chrome first) stopped at its first nonpassing cell, as counted runs do: 106 Chrome cells, 105 PASS (98 settled-WASM, 7 native), then `shift-End@cell-end/backspace` FAIL `sequence result differs from its reference`. Candidate and its fresh settled-WASM arm both saved `A1 cell tex` (one character removed); the bound native reference (run-01, ruling 2) saved `A1 cell text` (nothing removed). The single-line witness held, so the policy `native-if-single-line-otherwise-settled-wasm` chose native. Raw cells are `.json.gz` in that directory; the aggregate judge refuses the report (no `postConfig`, as for any stopped run).
2. **Census of run-01.** The source arms whose three native rounds have an empty Shift selection ("silent members": `shift-End@{cell-end,doc-end,empty-para,wrap-line-end}`, `shift-Home@{doc-start,empty-para}`, `shift-Left@{doc-start,range-one}`, `shift-Right@doc-end`; the same nine that are `settle-only` under ruling 3). In all nine, in every deletion family, **the first Backspace or Delete after the Shift key removes nothing**; `backspace-twice` removes one character, not two; `backspace-before-and-after` removes only the prefix's character. Delete at a document or cell end removes nothing anyway, so some of these cells coincide with the product.
3. **It is not timing.** `../s5-native/diag-settled-01/` (`diag_v23_native_s5_settled.py`, harness `v23_native_s5_settled.cpp`, built in-session): the same 54 silent-member deletion cells plus 12 non-silent controls (`shift-Left@caret-mid`, `shift-Right@range-fwd`, all six deletion families), with an 800 ms quiet settle after **every** member. **66/66 after-saves equal run-01's back-to-back saves**, 0 settle caps. Unlike the type family (ruling 3, finding 166), the deletion result does not depend on posting rhythm.
4. **Mechanism (source reading, 26.8).** `SwCursorShell::IsSelection()` is `IsTableMode() || m_pCurrentCursor->HasMark() || multi-cursor` (`libreoffice-26-8/sw/inc/crsrsh.hxx:951-955`): true whenever a mark exists, even with mark == point. A Shift+key that does not move still sets the mark. `SwWrtShell::DelLeft` (`sw/source/uibase/wrtsh/delete.cxx:167-191`) then takes its "if a selection exists, erase it" branch, deletes the empty range, clears the mark and returns; `DelRight` has the same branch (`:308`). So the first deletion after a no-movement Shift deletes nothing; the second behaves normally. This is Writer's shared key path, so desktop Writer very likely behaves the same; not measured on desktop.
5. **The product.** The ABI6 engine's `delete-backward`/`delete-forward` at a collapsed caret go through `startOrderedCaretDelete` (`wasm_sdk_probe/src/probe_engine.cpp:6281`, `:6298`), which builds its own one-character selection before deleting, and the page sends `delete-backward` because its state shows a collapsed caret. The product therefore deletes one character where Writer deletes none. `../s5-prep-04/` (uncounted, HEAD `9fd25b1b`+): six silent-member deletion cells in Chrome and Firefox, **10/12 FAIL** for exactly this (product removes one more character than Writer); the other two (`shift-Home@empty-para/delete`) PASS against settled-WASM because the single-line witness did not hold. The product is self-consistent: candidate equals its settled-WASM arm in every cell that has one.
6. **Scope.** At most the 54 silent-member deletion cells (9 arms × 6 families) can be affected; 18 are Left/Right (always native), 36 Home/End (native only with the browser single-line witness). Membership is a per-instance property of the archived native rounds (empty Shift selection in all three), the same rule ruling 3 used for `settle-only`. Non-silent deletion cells are unaffected (selection non-empty; prep-02/03 and counted-01's 7 native PASS). The type family is unaffected (typing over an empty mark inserts; run-03 `settle-only` cells pass).

## The question

Is Writer's empty-mark behaviour part of the Writer-parity claim that S5's native oracle stands for?

- **A. Yes.** The native saves stay the oracle. These are product FAILs; S5 cannot close until the product reproduces it (shell or engine; an engine change needs a relink by the owner), or until a separate decision ships S5 with a named failure.
- **B. No, it is a Writer defect.** For silent-member deletion cells, Writer's own result is not the target. Then what is the oracle? B1: the fresh settled-WASM reference (self-consistency only, as fallback A). B2: a native Writer save of the same deletion with the no-movement Shift member removed, i.e. what Writer does at the caret the user sees (a new native run of a different input sequence, which ruling 3 says is not an oracle for this one unless you rule otherwise). B3: something else.
- **C.** Another reading.

Coordinator's lean: **B1**, with the empty-mark behaviour opened as an upstream finding (167). Reasons, each checkable: a user cannot see the mark (no selection, caret unmoved), so "Backspace does nothing" is not a behaviour a user would ask the product to copy; the product's caret-delete path was built on purpose to delete exactly one character at a collapsed caret; reproducing the quirk would mean the page or engine tracking an invisible mark. Against B1: the S5 claim is Writer parity and these cells were bound to native by ruling 2 before anyone looked; switching an oracle after a counted FAIL is the shape §9 exists to police (conditions: before satisfaction — no S5 population has closed; forced and named — the counted-01 cell, the census and diag-settled-01; form — per-instance membership from the archived rounds; cutoff — the first complete clean S5 population per browser).
