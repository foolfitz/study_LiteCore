# T4: the product-path checks on v24, and every insert's route against its reply

Spec `specs/SPEC-M3-link-batch-v24.md` §6.3 T4 (ruling 1 T4; ruling 2 follow-up's payload note); default if not done or NE: v24 may not claim "paste unchanged". Written and committed before the first run.

## How it runs

`wasm_sdk_probe/tools/run_e2_c_product_path.py` (the product-path runner, ~50 checks, the page as served from `dist/` — after the cutover that is the v24 page `b15a6d8e…`), run unchanged through the new wrapper `tools/run_v24_t4.py`, which adds only:

- **Chrome**: a CDP `Page.addScriptToEvaluateOnNewDocument` observer (not a served file; no served byte changes) wrapping `Worker`. For every `insertText`, `replaceSelection` and `pasteMarkdown` request it keeps operation, payload keys, `route` (or `<absent>`), text length and wall-clock time; for its reply `ok`, `method`, `completion`, error code. Kept across the runner's navigations in sessionStorage, read out when the runner closes its session (`wire.json`).
- every stderr line wall-clock stamped (`steps.json`), so each `[step] … <outcome> <check id>` line bounds the requests before it.

**Named limit:** Firefox's WebDriver session has no preload script, so the Firefox run has check outcomes only; the per-request rule below is Chrome's. (The typed route in Firefox is already measured request by request in M2 and T5.)

The baseline is the last full product-path run on v23, `link-batch-v23/feature-protocol/product-four-arms-counted-01/{chrome,firefox}.json` (46 checks each, 2026-10-27, which `legacy-outcomes.json` there found identical to the original baseline on the 42 older checks).

## Rules (fixed before the run)

1. **Per request (form two, Chrome).** The population is every `insertText` request in `wire.json`, generated by the reader, not listed. Each must carry a `route`, have exactly one reply, that reply `ok`, and its `method` equal to the request's `route`. Non-vacuity: at least one request of each route (`uno-insert-text` and `paste`); otherwise NE.
2. **The paste-route checks (form two).** The set is generated from the wire: every check id whose step interval (after the previous `[step]` line with an outcome, up to and including its own) holds an `insertText` with `route: "paste"` or any `replaceSelection` / `pasteMarkdown` request. Each such check must be `PASS` on v24 **and** have the same outcome as in the v23 baseline (same browser; repeated ids compared as ordered lists). Firefox uses Chrome's set. An empty set is NE.
3. A check that compares request payload bytes and sees the added `route: "paste"` is a declared difference (ruling 2 follow-up), not a regression — but saves and replies must still be equal; such a case is named in the results, not waved through silently.

Recorded, not rules: every check's v24 outcome beside its v23 outcome in both browsers; the checks that hold typed-route requests (they changed route on purpose, so their outcomes are watched, not frozen); `replaceSelection` / `pasteMarkdown` replies.
