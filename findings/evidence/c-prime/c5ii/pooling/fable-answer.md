**1. Soundness.** A hybrid mode is sound only in this form: a pool is admitted from *same page, same runner, same browser, same flag class* single-run calibration reports, and a pooled run is accepted only if every member's owning check is FAIL **with the same boolean-leaf signature as its calibration** AND the pool's whole non-PASS set equals the union of the members' calibrated non-PASS sets. Anything else: the whole pool goes back to singles. All criteria below are per-instance on committed reports or tool-closed from `MUTATIONS` (CLAUDE.md §1). The catch is structural: same-page calibration *is* the 51 singles, so the sound mode saves nothing on the first census of a page. Using the previous page's calibration is the only version that saves time, and that version is screening, not evidence (collateral drifts across pages: measured below).

**2. Who qualifies on C′/Chrome today** (computed from the 42 reports, admission rule A2): **20 clean** (`backspace, boundary-move-takes-no-checkpoint, clear-format-leaves-one-format-on, composition-never-shown, cut, edit-arrows-swapped, enter-key-not-bound, focus, gesture-abort-not-wired, ignore-a-document-that-grew, keyboard-formats-not-bound, one-tile-for-the-whole-document, open-button-forwards-nowhere, paragraph-action-swallowed, paste, projection-not-wired, resize-does-not-repaint, sample-picker-does-nothing, worker-crash-is-never-noticed, worker-crash-throws-the-checkpoint-away`); the boundary trio may not share a pool (same owning check; the two worker-crash anchors nest). **31 must stay single** (collateral FAIL or NE, flags, declared undetectable, declared alsoRed/alsoNE, special reading rule, under diagnosis, recovery pair flipped, not yet calibrated). ## 1. Admission criteria (CLAUDE.md §1 form)

For a mutation M to be poolable on page P / runner R / browser B / flag class F:

- **A1 calibration exists** (per-instance, from a committed report): a single-run report with `mutation == M`, `complete: true`, no `sessionDied`, whose binding fields equal the pooled run's: `servedShell.declaredSha256` (bundle), the unmutated entrypoint sha (the chain's `dist` sha; for candidate runs `candidateSource.sha256BeforeRepoint`), runner sha (currently only in `chain.txt`, not in the report — the pooled reader must take it from the chain line or the report must gain it), `browser`, and flag class (`candidateCutover.profile` / `refusalDiagnostic` present or absent).
- **A2 no collateral** (per-instance, tool-derived from the report, not from `alsoRed`): the set of checks with outcome ≠ PASS is exactly `{M.check: FAIL}` plus a subset of the designed pair {`a-refused-action-is-reported-and-changes-nothing`, `notice-action-recovers-the-session`} at NE. This excludes NE collateral too (NE on a partner's check means the partner cannot be judged → wasted split).
- **A3 no declarations** (tool-closed from `MUTATIONS`): M carries none of `alsoRed`, `alsoNotEstablished`, `requiresFlag`, `expectedToBeDetected`. A declared blast radius is a prediction, and this tree's own comments say predictions went stale (`:2014-2018`, `:1713-1727`).
- **A4 distinct owning checks** (tool-closed): no two members share `check`.
- **A5 disjoint patches** (tool-closed from `MUTATIONS` + dist): for members on the same `path`, `find` strings neither equal nor contained, and applying all members' replaces in any order leaves each `find` matched exactly once before its own replace — the multi-patch analogue of `test_every_mutation_matches_its_target_exactly_once`. Today's conflicts: identical anchors `selection-shape-*` (2), `paragraph-action-swallowed/misrouted/toolbar-drops-the-list-action` (3), `cut-swallows-the-refusal/cut-falls-back…` (2), `undo/undo-twice` (2); nested anchors `worker-crash-is-never-noticed` ⊂ `worker-crash-throws-the-checkpoint-away`.
- **A6 plain control** (per-instance): the plain run on P/B has every member's owning check PASS (the counted plain reports already exist per release).

Dynamic test of form (CLAUDE.md §1): add a fictitious 52nd mutation — A2 refuses it (no calibration), A5 recomputes; nothing hand-written needs editing.

## 3. Masking vs interference

- Safe direction (interference): a partner makes B's check NE or PASS, or the pool's non-PASS set gains anything → V3 fails → split → singles. Cost: one wasted run. Example from the data: `line-movement-keys-unbound` makes the boundary check NE.
- Dangerous direction (masking): B dead, partner A reddens B's check. Defense 1 = A2 disjointness on same-page calibration (A has no collateral at all). Defense 2 = signature: the set of boolean/None leaves of `checks[i].observed` must equal B's calibration. Evidence that defense 2 alone is insufficient — identical signatures between owner and collateral on C′: `checkpoint-write-fails`/`checkpoint-before-selection-noop` vs `boundary-move` on the boundary check; `caret-ignores-x` vs `caret` on caret-drawn; `format-ignores-a-selection` vs `keyboard-formats-not-bound`; `slow-repaint` vs `ignore-a-document-that-grew` and vs `format-ignores-a-selection`; `save` vs `paste`. Evidence that it adds real discrimination: it differs for `caret` vs `line-movement-keys-unbound` (`takenByThePage` true vs false), `cut` vs `caret-off-by-one-line` (`handled`, `documentUnchanged`, `neighboursSurvive`), `clear-format` owner vs `slow-repaint` (`allOn.italic/underline`), the three `recovery-returns` mutations against each other, and the boundary check between B3-failing and B4-failing mutations.
- Residual risk with same-page calibration: B dead AND A acquires an *intermittent* FAIL collateral on B's check with B's signature in the pooled run but not in A's calibration run. No instance in the data; intermittent collateral seen in this tree is NE (`clear-format…` toggle, finding 077), which is the safe direction. With previous-page calibration the risk is ordinary drift (measured in §SUMMARY 3), which is why that mode is screening only.
- Staleness rule (per-instance, all fields are in the reports except the runner sha): calibration is valid only while page entrypoint sha, `servedShell.declaredSha256`, runner sha, browser and profile/flag are all equal. A runner change invalidates even if the page is unchanged (the `projection-not-wired` and boundary signatures changed between gate-4a/096 and C′ because the checks gained fields).

## 5. §34 cost and when the mode may be used

- Changes: `--mutate` multi-valued + multi-override mirror (`:4479`, `:4778`, `build_mirror` already dict-based) — this touches the runner §34.1 freezes and moves `bd6fc0caf677ee9c`, which C5 (ii) and the coming 0.2.12 count bind; an A5 static test next to `test_product_path_mutations.py:146`; a pooled-verdict reader (new judging tool: §34.3 one dual review, whose fixes raise 因審核而修; the owner watches that number globally, `HANDOFF-2026-10-11c…:30`); a calibration index keyed by the A1 fields.
- Witness: none. No committed report shows a single run judged wrongly or an execution voided by the single-run design. §34.4: register one line, no code. §34.2: a masked dead mutation would be an honest accident, so the design must defend against it (it does), but the defense is new machinery, which §34.8 and CLAUDE.md §4 push against.
- If adopted later: allowed for development screening between releases (previous-page calibration, pools ≤3, every member re-run single before the release census); never for C5-type claims, release counts, or anything cited by hash; a full single census remains mandatory on any page or runner change before a release.
