## 3. Rules to append to the spec (as §34; each with its default if never done)

- **34.1 Freeze.** From the commit that sets `BINDING` until the X7 verdict is read, no edit to `judge_counted_m2.py`, `run_merge_wasm_shakedown.py`, `check_profile_identity.py`, `check_merge_key_undo_scope.py` or the product-path runner, with two exceptions: (a) a crash on an honest run (traceback, no report) — fix, re-run that step only; (b) a FAIL shown to be a reader bug by a witness report — fix with the witness as the red case, re-judge, do not re-run. *Default if never done:* the reader's X7 verdict stands as printed, red included.
- **34.2 Threat model.** Checks defend against accidents in honest runs: wrong flags, stale `dist/`, a moved page, a skipped step, a partial run, a crashed browser, a deleted key in a generated file. They do not defend against forged or hand-edited reports, patched constants, or reports no committed runner can emit. A scenario needing such an input is not a defect in a check; it is at most a NOTE in the finding index, never code. *Default:* every green-while-broken scenario stays actionable and the loop has no end — the state the owner is afraid of.
- **34.3 Review budget.** One two-seat adversarial review per new judging tool, before its first counted use, none after. The counted-M2 reader's review is spent (`v19/review/`). Later reviews address product changes; a reviewer of a check is briefed "name a committed report whose verdict changes", not "construct a scenario". A reader rewritten by more than half is a new tool and gets one review. *Default:* no review; the first counted run is the test, which 34.1 accepts.
- **34.4 Findings about checks need a witness.** Actionable only with an honest run's committed report that the check misjudges or wrongly voids; otherwise registered in one line, no code. Each handoff reports two counts: check-fixes triggered by runs, check-fixes triggered by reviews. After 34.3 is spent, a non-zero second count is a rule breach, not a finding. *Default:* the counts are not reported and inflation is invisible — then 34.3 is the only brake.
- **34.5 Binding breadth frozen at nine `BOUND_KEYS`.** A tenth needs a witness per 34.4 (a run misjudged because the unbound thing moved). Reason: every key is one more way to void a run. *Default:* nine.
- **34.6 Criteria text stays.** Guards may catch up to text already in the spec (§33.3), never to new text; new criteria only by §9's four conditions. The eight §33.4 registrations stay registered; none blocks the link, the bind, or X7. *Default:* none added, none promoted.
- **34.7 Named limit, not fixed now (34.4 applied to itself):** the product-path reader "exits 0 on a MISS as well" (`v18/RESULT.md`, Q3); its verdict is the `SUMMARY` line. X5's chain reads that line; a `judge.py` exit code is not evidence there. A witness would be a chain that treated a MISS as pass. *Default:* read the line; register.
