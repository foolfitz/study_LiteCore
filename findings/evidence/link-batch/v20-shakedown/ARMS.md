## The arms

Criterion forms are CLAUDE.md §1's: **form one** = a per-instance property over a list the tool itself produces; **form two** = a tool-closed enumeration. Every arm states its default if it is never run.

### P1 — the page number, per position (form one; §5 P1 as rewritten by §10.8)

- **Fixtures.** (a) The 60-page document, `create_long_document.build(60)` built in memory (the generator does not fix zip timestamps, so its sha256 is recorded per run, not predicted); page k has the heading `LD-PAGE-k` and 18 lines `LD-Pk-L1..18`. (b) The mixed fixture, `create_mixed_page_document.py` (deterministic, sha256 `e7f7611fd86e53243b7ab791283770a5612da236b19c41aab6064f0e8eb62b0a`, 8 pages: A4 portrait, A4 landscape ×2, A5 portrait, US Letter, A4 portrait, A3 landscape, A4 portrait), measured natively in `../page-rectangles/MIXED.md` (3/3 rounds identical). Both are opened through the product's own file input from the mirror root.
- **Rectangles.** The engine's reply to the page's own `pageRectangles` request, captured by the observer on the worker's `message` port (raw string, `parts`, document size). The runner parses the raw string itself (`x, y, w, h; …`, twips). The list of positions is **generated from those rectangles**: for every page k its centre `y_k + h_k/2`; for every adjacent pair (k, k+1) the middle of the gap `(y_k + h_k + y_{k+1}) / 2`. That is the tool-closed list P1 is judged over (60 + 59 and 8 + 7 positions).
- **Point-to-page rule, as the task requires it to be stated:** a document-space point is mapped to a page by **"inside a rectangle" on the y axis only**; x is ignored because the region the page intersects is the full document width (`visibleRegionTwips` sets `x: 0, width: widthTwips`; the page never scrolls sideways; Writer's rule is about vertical overlap). A y inside the 284-twip gap is inside **no** rectangle; the boundary positions therefore take their expectation from the view region, not from the point. Nothing is "nearest rectangle".
- **Scrolling.** For each position the runner sets `#desk.scrollTop` so that the position's document y is at the vertical middle of the desk's view (`paper.top` offset + `y / heightTwips × paper.height − desk.clientHeight / 2`), waits until the page is quiet, then **measures the visible region itself**: `#paper` and `#desk` bounding rectangles → device rows `[top, bottom)` → twips with `heightTwips / paper.height` (the document height is the one the pageRectangles reply carries). It then computes the expected span by Writer's rule on **whole rectangles** (strict `<` on both axes, string order, never sorted, nothing inferred from heights) in Python. This is an independent implementation of the same rule the page uses (36 unit tests in `page-number.test.mjs`), so **what P1 checks is the wiring**: the rectangles reached the page, the view is converted at the right scale from the right scroll geometry, the text is formatted, `hidden` is cleared. It does not re-prove the rule.
- **Criterion (per position):** `#page-status` is not `hidden` and its text equals the runner's expectation: `第 k 頁，共 M 頁` when the measured view overlaps exactly one rectangle, `第 a–b 頁，共 M 頁` (U+2013) otherwise, where M is the number of rectangles in the reply. Also, once per fixture: M equals the reply's `parts`.
- **Prediction.** At a window of 1400×1000 CSS px the 60-page fixture's view is about 11,000–12,000 twips tall (12,474 twips over a 900 px paper, desk ≈ 850 px), shorter than an A4 page (16,838), so every centre reads a single page and every boundary reads `k–k+1`. The mixed fixture's document is 24,379 twips wide, so at the same window the view is about 23,000 twips tall and **taller than every page**: centres would read spans. The mixed fixture therefore runs at a **reduced window height** (Chrome `Emulation.setDeviceMetricsOverride`, Firefox `MOZ_HEADLESS_HEIGHT`), chosen so the view is shorter than the smallest page (11,906 twips, ~ desk < 439 px). The runner records the achieved desk height and view height in twips, and per fixture `singlePageViewPossible`. If the view turns out taller than a page, the expectation is still the rule's output (a span) and the position is reported with `viewTallerThanPage: true`; the criterion is unchanged, the reading is simply less discriminating and the report says so.
- **Recorded, not compared:** native page counts (60 and 8, from the native rounds); `parts`; the time from the open to the first rectangles reply; how many `pageRectangles` requests the open took.
- **Red cases (judge, made red before the first run):** a report whose one position has the text's k off by one → FAIL; a position with `hidden: true` → FAIL; `M ≠ parts` → FAIL; **non-vacuity**: a report with no rectangles reply or zero positions → NOT_ESTABLISHED, never PASS.
- **Default if never run:** item 3 (the page number) does not ship (§5 P1).

### P2 — M follows an edit (form one per edit; §5 P2 as rewritten by §10.8 and §12.3)

- **P2-a, add a page.** 60-page fixture, shipped worker. The runner clicks inside the last page's text (document fraction from the rectangles: page 60's y plus about 6,000 twips, the last text line), presses End, then presses the real Enter key (`insert-paragraph-break`, in the manifest) one press at a time with the queue drained between presses (finding 111 is not this round's subject), until the engine's latest `pageRectangles` reply carries 61 rectangles, cap 60 presses (prediction: 61 appears after roughly 30–35 presses; A4 body 14,570 twips, page 60 holds a heading and 18 lines of ~276 twips). After the last press, no input. **Criterion:** at +2 s after the last press, `#page-status` reads `共 61 頁` and the latest reply's count = `parts` = 61. **Recorded:** the time from the press that added the page to the first reply with 61 and to the text change; which trigger preceded that re-read (a paint reply with `documentSizeChanged: true`, or an editor-state push whose `documentSizeChangedCount` advanced). The original P2 wording "within the next paint" is recorded by that timing, not judged.
- **P2-b, delete a page.** Then the same number of real Backspace presses, drained between presses (each merges an empty paragraph: finding 117's path, fixed in v19 and measured at 30–36 ms per press). **Criterion:** at +2 s after the last press, the text reads `共 60 頁` and the latest reply's count = `parts` = 60.
- **Red cases:** a report whose +2 s text still says 60 after the add → FAIL; a report where the text's M and the reply's count disagree → FAIL; a report with fewer than one add press → NOT_ESTABLISHED.
- **Default if never run:** item 3 does not ship.

  - **Reading (fixed now):** `ESTABLISHED` if at least one lone id-13 occurs on a product-reachable path (open, settle, Enter, Backspace, scroll) — then finding 138 was BLOCKING-grade before the count; condition 45 (v67's `placeCaret` acknowledgement) has already fixed it on the page, and the README must say so in its first lines. `NOT_ESTABLISHED` if none occurs — then "the counter pushes its own editor-state" stays covered by reading the source only, as §12.3 says.   - **Red cases (reader `--self-test`):** a synthetic trace with one id-13 and nothing else within 25 ms → ESTABLISHED; the same with an id-0 at +3 ms → not lone; an empty trace → NOT_ESTABLISHED and "no lok events seen" (the instrument did not run), never a quiet NOT_ESTABLISHED.
  - **Default if never run:** `NOT_ESTABLISHED` by default; finding 138 stays at review 6's grade (SHOULD, fixed in v67).

### P3 — scrolling calls no engine (form one over the requests observed; §5 P3 as rewritten by §10.8)

- 60-page fixture, shipped worker, after open and settle. The observer counts every request the page posts to the worker, by operation and time. The runner scrolls `#desk` from the top to the bottom in steps of one view height, 150 ms apart, and back to the top, then waits 2 s.
- **Criterion:** every `pageRectangles` request posted during the scroll window has a trigger within the 2 s before it — a paint reply with `documentSizeChanged: true` or an editor-state push whose `documentSizeChangedCount` advanced (§10.8: "計算時排除由大小改變觸發的重讀"). With no edit none is expected, so the predicted count is **0 requests, 0 triggers**. **Non-vacuity:** the scroll must have driven the page — at least one `paint` request during the window, and `scrollTop` must have reached the bottom; otherwise NOT_ESTABLISHED.
- **Red cases:** a synthetic report with one untriggered `pageRectangles` request inside the window → FAIL; a report with zero paints in the window → NOT_ESTABLISHED; a report whose scroll never reached the bottom → NOT_ESTABLISHED.
- **Default if never run:** recorded as unverified; does not block shipping (§5 P3).

### E2 — `caretBefore` equals the caret before the key (form one over the refusals observed; §5 E2 as amended by §10.6)

- `caretBefore` is **data only in this link** (§13.3; the page reads nothing from it); this arm establishes whether the data is right. Instances are the refusals reachable on the standalone page under C: **C17** (Delete at the end of `M17 cell one`, native `refused-k1-anchor` → `anchor-mismatch`), **F01** (Delete at the end of `F01 frame first`, inside a text frame, N1 → `anchor-mismatch`), **F02** (Backspace at the start of `F01 frame second` → `anchor-mismatch`), **C15** and **C16** (`key-noop` → `key-deadline` with `keyPosted: true`, refusals that also pass through `finishMergeKeyError` and so carry `caretBefore`). - **Hold arm (§10.6 "按住跨過一次併段"):** Delete **held** for 2 s (one press, repeats every 30 ms from 500 ms on, the desk's settings; CDP `autoRepeat` on Chrome, a WebDriver action chain on Firefox) at the end of `M13 number two`: the first press merges `M15 before table` into it (native `merge`), and the repeats continue to the end of the merged paragraph, where the table begins (C15's position, `key-noop` natively → a `key-deadline` refusal). The instance is the **first refusal of the hold**; its reference caret is the last caret the engine pushed after the merge completed and before that refused request was posted.
- **Criterion (per refusal):** the refusal's `caretBefore` is present with `rect` not null, and `rect` equals (all four fields) the last `editor-state` caret the engine pushed in the same worker generation before the refused request was posted; `caretBefore.sourceSequence` is ≤ that push's `sourceSequence`; `source` is recorded (P or cache, §10.6). - **Red cases:** a synthetic report with `caretBefore.rect` differing from the prior caret in one field → FAIL; `caretBefore` absent → FAIL; `rect: null` → FAIL; a report with no refusal at all → NOT_ESTABLISHED (not PASS).

### E3 — L-136-rule-iii-residual (§5 E3): registered "no reachable instance", not run

- E3 wants a stage error induced **between Escape #1 and #2** of the E-shape and the reopened caret equal to the pre-key caret. Read from source: the only inducers of a mid-transaction stage error in this tree are diagnostic configurations (`run_e2_c_product_path.py --refusal-diagnostic` withholds an action in the manifest; the merge model's REPORTED sequences need extends, which v20 does not offer; every command is BUSY while a barrier is in flight, `probe_engine.cpp` ~6101). The shipped configuration offers no way to make K2 or the Escapes fail on demand. This is CLAUDE.md §3's second kind — **judgeable only in a diagnostic by construction** — not an unguarded hole. Registered as "no reachable instance in the shipped configuration", as §5 E3 itself provides.
- What this round does instead: E2 records, for every refusal it observes, the reopened caret against the pre-key caret. Should any observed refusal be a stage error after K1 (`return-mismatch`, `unit-late`, `undo-read`), that instance is reported as an unplanned E3 instance with that comparison.
