Prior rulings this stays inside: SPEC-M3-paragraph-merge §3.2 (a key's evidence is only a callback that differs from what was known at dispatch; `specs/SPEC-M3-paragraph-merge.md:80-90`), §15.1 / §16.1 (every step must leave a trace; any rectangle change can forge a cursor; `:497-533`), §34 (checks guard honest accidents; no new checking machinery unless a criterion would pass a broken product in an honest run; `:1164-1250`).

Two facts this ruling turns on that neither the spec nor the review stated, both confirmed in the tree:

- **F1.** The LOK flush deduplicates `TEXT_SELECTION` and `INVALIDATE_VISIBLE_CURSOR` against the last payload sent (`desktop/source/lib/init.cxx:1592`, `:1594`, `:2530-2537`), and Writer flags `TEXT_SELECTION` on every selection repaint, with the payload computed only at flush (`sw/source/core/crsr/viscrs.cxx:526`; `init.cxx:2485-2486`). So an operation that leaves the selection empty-before and empty-after sends **no** `TEXT_SELECTION` at all. This is why the merge key's late flush cannot forge the transition rule (B1), and why the engine already relies on exactly this when it waits for Escape's "becomes empty" (§16.2).
- **F2.** Typing emits **no** `INVALIDATE_TILES` on this engine: natively 0 of 6 runs (`findings/evidence/link-batch/page-rectangles/README.md`, Edit B) and on WASM 0 over 140 keys in eight runs (`findings/evidence/typing-latency/r2-blit-bytes/README.md:9`, `:41`, `:57`). `documentChangeSequence` advances only on `INVALIDATE_TILES` (`wasm_sdk_probe/src/probe_engine.cpp:2632-2633`). So a page-number re-read keyed on `documentChangeSequence` would never fire for a page added by typing. `LOK_CALLBACK_DOCUMENT_SIZE_CHANGED` fires 1.2-1.8 ms after the edit, and the rectangles are already current when it does (poll arm, 6 of 6; page-rectangles README "Additional arm"). That overrules the main session's S-10 lean.

## RULING

### B1 — what an extend, and a move that starts on a range, may complete on

**(a) is adopted. (b), (c) and (d) are not.**

- **(a) Transition rule.** For an extend from any start, and for a plain move whose start is a range (judged, as today, from the engine's cached `selectionRectangles` at dispatch), the completion is: a `LOK_CALLBACK_TEXT_SELECTION` whose parsed rectangle list differs from the list cached at dispatch (empty vs non-empty counts as different), followed by the next `LOK_CALLBACK_INVALIDATE_VISIBLE_CURSOR`; the state serialised is the cache after that cursor. The 250 ms readback (`EditorMoveReadbackDeadlineMs`, `probe_engine.cpp:465`, `:5499-5502`) stays as the fallback and keeps its name `verified-move-readback`. Plain moves from a caret keep today's rule (`EditorCaretOrSelectionCallback`, `:5470-5472`): one variable per link.
  - This is §3.2's rule applied to the selection, and §16.1's reason applies unchanged: the trace of a Shift+key is a selection that differs, computed at flush and deduplicated only against the last value sent (F1), so it can neither be forged by a relayout nor dropped. The native run supports it in every changing cell: 74 Shift cells each with exactly one `TEXT_SELECTION`, the 24 plain-on-range cells each with `SEL0` differing from the range, the cursor always last (`findings/evidence/link-batch/extend-signatures/README.md`, Tables 1, 2, 5).
  - **The residual, named (L-extend-prior-flush):** an operation that completed before its own flush, whose late flush carries a `TEXT_SELECTION` that differs from the extend's dispatch cache, completes the extend early with that operation's state. By F1 the population is: `insert-text` over a non-empty selection (`handleInsertText` answers synchronously, `:3186-3221`; the paste collapses the selection, so its flush carries `SEL0`); and any readback-completed operation (`EditorSelectReadback`, `EditorPlaceCaretReadback`, `EditorActionReadback`, `:5932-5946`) whose own `TEXT_SELECTION` arrived after 250 ms. **Not** in the population: the merge key (its flush is empty-to-empty, F1) and plain moves from a caret (no `TEXT_SELECTION`). The effect is one stale completion reply; the engine's next `editor-state` push carries the true state with a higher `sourceSequence`, which the page's guard accepts (`editor-shell-v2/narrow-editor-v2-session.js:188-200`). The document is never changed by it. What the user can see is a follow-up delete routed from the stale snapshot and refused by the gate (`:5285-5300`) or by the barrier's own `readSelection()` precondition (`:4004-4010`): a toast or a 119-style reopen, nothing deleted. S5 (B2) counts it.
- **(b) rejected.** It needs a "flush seen" signal for each synchronous completion. The only candidates are a cursor callback (forgeable, §16.1) or `documentChangeSequence` (does not advance on typing, F2). Every such signal would also need its own deadline and readback. That is a second engine mechanism in the same link for a residual that (a) already bounds and names (N-9).
- **(c) rejected.** A poll of `getTextSelection` has the same hole as (a) (the previous operation's effect) and adds a SolarMutex round every poll on the engine thread; `readSelection()` is the call measured to hang on finding 038's construct (`:909-911`). It also cannot supply what S2 compares: the rectangles and the caret come only from callbacks (S-4), so (c) would still have to wait for the same `TEXT_SELECTION` and cursor.
- **(d) rejected.** The owner asked for Shift+Arrow by name (spec §1). (a) is sound with a named residual; narrowing is not needed.

**S2's added population (remedy ii): both, with different roles.**

- The rule is a pure function in a header (the pattern of `merge_key_undo.hpp`, spec §3.1 item 11), fed by the dispatch snapshot and each parsed callback. Its test is tool-generated from the LOK model that `tests/merge_key_undo_model_test.cpp` already has (FIFO of posted events and flushes, flush coalescing and dedup, events straddling a transaction start; `:14-32`), extended with a synchronous insert whose flush is still queued and a readback-completed operation whose flush is late. This is form 1 and it is the criterion for the rule. Red cases: §9's rule (first cursor) and v19's rule (first `TEXT_SELECTION`) must fail "insert then Shift+key" and "type over a range then Shift+key". The generated sequences on which (a) is stale are printed by the test as L-extend-prior-flush's population; the test asserts the rule is exact on every other sequence.
- The three sequences (insert then Shift+key with no wait; a merging Backspace then Shift+key; Shift+Right held 1 s) are also arms in the existing product-path runner (`tools/run_e2_c_product_path.py`), not a new runner, run as counted arms (N runs, the count written before the run; a pass is "N of N" with the stale-completion count listed, not averaged). They measure the WASM thread interleaving the model cannot; the model measures the interleavings a browser cannot be made to produce on demand.

### B2 — the delete routed from a mid-flight snapshot

**Late binding, inside the queued item. Not an in-flight count.** S5 is **form 2 over S1's cells**, not a fixed list.

- The session's queue runs one item at a time and writes `editorState` from each item's result or from `getState()` before the next item starts (`editor-shell/editor-session.js:287-311`). So an item that chooses between `delete-backward` and `delete-selection` when it runs sees every earlier move and extend completed. An in-flight count cannot choose a form: while a move is out, the shape is unknown, so the choice has to be deferred anyway, which is late binding. (A count of moves and extends in flight is still needed, for S-12's pacing only.)
- The choice is made from the session's own snapshot at run time, through a session method that takes a resolver (shell change, new generation, which this link has anyway). It is not made by the page awaiting move promises before enqueueing: that would let a character typed after the Backspace enter the queue first, finding 111's shape (`narrow-editor-v2-session.js:642-656`).
- Finding 131's rule A (`deletesInFlight > 0` keeps the key's own collapsed form, `web/e2-editor-app.js:2403-2406`) is kept as written; at run time a delete in flight cannot exist (the queue is serial), so late binding gives rule A's answer on the 131 arms, which must stay green (witness: the existing 131-B run on v20).
- **S5:** population = every Shift cell of Table 1 (84, from the native `arms-r*.jsonl`), each followed with no wait by Backspace, by Delete, and by one typed character; Writer's reference comes from the native tool for the same sequence. Oracle: `content.xml` byte-equal for the Backspace and Delete arms; for the typed-character arm the paragraph-text-sequence comparator of SPEC-M3-paragraph-merge §12 (rsid makes typed bytes unequal across sessions, `:363-380`). Default if never done: the page does not send `extendSelection`. A fixed short list is form 3 (AGENTS.md §1) and is refused as a hard criterion.

### B3 — C's late Shift

**The review's shape is adopted with one change: a K1 selection that arrives inside the window takes the ordinary path, it is not refused.**

- After the first 250 ms `NONE` (`rejectSelectionBarrierAtDeadline`, `:3843-3861`), the transaction stays in `AwaitingUnitSelection` for one more `MergeStepDeadlineMs` (2000 ms, `:549`). If K1's `TEXT_SELECTION` arrives in that window it goes where it goes today (`handleSelectionBarrierStateCallback`, `:3901-3906` → `UnitVerificationQueued` → merge, delete, or that path's own refusal). The attribution's P and the anchor fence were set up before K1 (`:4028-4040`; `merge_key_undo.hpp:140-150`), so a late K1 is the same K1 with the same proof; refusing it would need new code (a "past the first deadline" flag → `unit-late`) and would turn a slow but correct Backspace into a reopen. If the window expires with a second `readSelection()` still `NONE` and the typed selection still collapsed, the action completes as `verified-boundary-noop` (`changed: false`, revision unchanged, `boundaryNoop: { waitedMs }`), no `EDITOR_BOUNDARY_UNSUPPORTED`, no reopen. The two other exits at that second read stay as today (`unit-late`; `EDITOR_STATE_UNAVAILABLE`).
- 「收回成 barrier 之前的游標」 is dropped. The review is right that it names no mechanism: `setTextSelection RESET` is synchronous and runs before a queued K1 (`sw/source/uibase/uno/unotxdoc.cxx:4066-4067`); the E-shape is asynchronous with its own failure stage.
- **The window is long enough against finding 135:** the measured stall is 196.6-210 ms (`findings/135-...md:16`), K1 is posted before the first 250 ms deadline, and the window adds 2000 ms; a K1 slower than about 2250 ms is the residual, named **L-C-late-K1**: it lands as a selection in a live session; the document is unchanged until the next key, and the next typed character replaces that unit. It cannot be closed: at the true document start or end K1 produces no callback of any type (native P-b, Table 5), so there is no signal to wait for, only the window. The number is the existing step constant, not a new one (§4: a number is changed only by an appended section naming the measurement that forced it); C1 records `waitedMs` so that a later section can shorten it if the owner finds a 2.25 s boundary press too slow.
- C1's busy arm becomes the per-completion criterion as the review wrote: at least 500 ms after every `verified-boundary-noop`, `editor-get-state` reads `selectionType` `none` (form 1). The old busy arm (count `late-selection` in 12 runs) is withdrawn: by construction it would read 0 whether or not C is broken.
- The shell client's completion whitelist must accept `verified-boundary-noop` with `changed === false` and an unchanged revision, with a red case (M1-3's shape); the page must neither toast nor reopen on it; 132's pacing and 134's B apply unchanged.

## WHY (for the owner)

Shift＋方向鍵完成的證據改成「選取範圍真的變了，然後游標到」，這就是併段那份規格已經裁過的規則，理由也一樣：選取是在送出那一刻算出來的、重複的不會再送，所以偽造不了。它剩下的破口只有一種：前一個「不等回呼就回報完成」的操作（打字蓋掉選取、或等到期限才讀回的操作）把它的尾巴塞進來，結果是一次回報的狀態是舊的、下一下刪除可能被拒，但文件不會被改錯；這一條登錄成具名限制並由 S5 逐格數。頁面那邊，刪除要用哪一種形式改在排到它執行時才決定，因為佇列本來就一次跑一件，那時前面的 Shift 都已經完成。C（在文件兩端按 Backspace 不再重開）改成先多等一段既有的 2 秒再判「沒東西可刪」；若 Shift 晚到卻在這段時間內到了，照原本的路走，不拒絕。代價是文件開頭按一下 Backspace 要 2.25 秒才回來，這個數字會被記下來，之後嫌慢可以憑量到的數字縮短。「拒絕出口一律不留選取」這一項撤掉：每一種拒絕都會重開或鎖住佇列，留下的選取使用者碰不到，而且它的清單是手寫的。頁碼改在核心送出「文件大小變了」時重讀，因為實測打字根本不會送 tile 失效，主 session 原本挑的那個觸發點抓不到打出來的新頁。頁碼放畫面底部、範圍上的方向鍵這一批就交給 Writer、頁碼不用核心算。修訂後的規格再送一次有限的審核（只看追加那一節、問題先列好、不再有第三輪），然後才寫程式。
