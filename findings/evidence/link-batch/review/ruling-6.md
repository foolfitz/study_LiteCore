### Q4 — the scheduler after BUSY (F6): **apply** `_issuedAt = null` in the error branch, with two tests; §34 does not apply

- Confirmed in `narrow-editor-v2-session.js:289` (the early return on an equal counter), `:323–337` (`_issue` records `_issuedAt`, `_settle` leaves it on failure). Every command is BUSY while a barrier is in flight (`probe_engine.cpp:6100–6106`), so a size-change push during a merge issues a read that fails, and the drain's state write after the merge carries the same counter and is ignored: the line stays hidden until the next counter change, reopen or paint-reported size change. Review 6 §3 requires a re-read after BUSY.
- `this._issuedAt = null` on failure puts the scheduler back in its "no read issued for this document" state, so the next state write of any kind re-reads. Retries are bounded by state writes, and the action that caused the BUSY always ends with one (the drain writes `editorState` after every item), so a retry is guaranteed. Not scoped to the BUSY code: a torn reply (`PAGE_RECTANGLES_INVALID`) is followed by its own counter push anyway, a timeout means the session is dying, `UNSUPPORTED_OPERATION` is gated off by `offered()` — one branch, no code string to drift. The cost is a corrected sentence in README §3: a read that always fails costs one read per state write while it fails, not one per trigger.
- F6's "pushes during a read are already covered by `_again`" is imprecise: a push during a read is coalesced only when its counter differs from `_issuedAt` (`:289` returns otherwise). That is still enough for review 6 §3's push requirement, because a push with an unchanged counter carries no size information — a size change that happened before or during the reply's construction arrives with its own counter.
- Product code, not a check: §34 is not engaged.
