## The model (tests/extend_completion_model_test.cpp)

The merge test's LOK model with 12.1's shapes, all read from source before being modelled:

- One FIFO of posted keys and flushes (`postKeyEventAsync` posts a user event; a repaint flags updated types and schedules one flush, `setUpdatedType` -> `scheduleFlush`; a repaint while one is pending joins it). A flush computes its payloads at its start, after any already-queued `UNO_COMMAND_RESULT`, in the order START, END, TEXT_SELECTION, cursor; TEXT_SELECTION and the cursor are dropped when equal to the last SENT (init.cxx:1592-1594, 2530-2537); START/END are never dropped. One rectangle per line for the selection, as Writer sends it (so a two-unit selection passes `geometrySafe`).
- One line of four units; text 0 = a b c d, text 1 = a b E c with E a two-code-point grapheme. Shift+Left/Right/End, plain Left/Right and the barrier's own Shift+Left have real effects; an empty mark is not a selection (`HasSelection`, crsrsh.cxx:3040). A plain arrow on a range clears the mark and moves one unit from the point (the model's choice; natively every plain key on a range sends SEL0 CUR). A key that changes nothing produces no callback (P-b).
- Two threads: the LOK thread does one step per tick (a key, or one callback of a flush); the engine's decisions that need no mutex (a command's dispatch snapshot, a readback deadline, the page's resolver) land between any two steps, so a snapshot can be taken while a flush is half delivered; its synchronous LOK calls (postKeyEvent, paste, setTextSelection, .uno:* with a listener) wait for an event boundary (the SolarMutex). `lag` = LOK steps between a decision and its landing; lag 0 = before the next step.
- Earlier operations, every one generated: synchronous insert at a caret and over a range (reply at once, flush queued); a move completed by its readback deadline (Shift+Left/Right, Left/Right from every shape, deadline lag 0-3); uno-command-result completions (delete-selection on a range, undo restoring a selected unit, an inline format with a RESULT-only flush), serialised at RESULT ahead of the same flush's SEL/CUR; a product select-range (pending on TEXT_SELECTION, readback armed) as RESET, START, END with a flush allowed between each pair. The user's move: none, Shift+Left, Shift+Right, Shift+End, Left, Right; registration lag 0-5 after the earlier completion; readback deadline lag 0,1,2,3,4,6,9 after its key post.
- The page (12.4): one item at a time; the delete's form is bound when the item runs from the session's snapshot -- the last completion reply or push, or `getState()` (an active selection read) when the previous item's reply carried no state (the insert); rule A keeps the key's own collapsed form right after a delete. Backspace timings: resolution lag 0-3, the barrier's 250 ms read lag 0 (before K1 runs, a 135-style stall), 1 (between K1 and its flush, today's `EDITOR_STATE_UNAVAILABLE`), 9 (after); verifier lag 0-1.
- The barrier (probe_engine.cpp ~3785-3895, ~4004-4049): core NONE and a collapsed cache before K1; K1's TEXT_SELECTION queues the verifier (readSelection, one rectangle, text without a separator; MergeKey never arises on one line); the flagged one-code-point rule; `.uno:SwBackspace` synchronous, completion on the collapse SEL0 plus the acknowledgement; C's window (10.5) waits until core is idle and answers verified-boundary-noop or, flagged, a refusal. `AwaitingDeleteCompletion` carries no deadline, as in the engine (only the merge stages and the first 250 ms read do).
- Writer's reference: the same keys and commands applied in order with no engine in between; a refusal must leave the text as it was before the Backspace.
- Rule (a)'s property: at a Transition completion the cache (selection rectangles and caret) equals core's state right after the move's own key ran. Each stale sequence is printed with its class, decided by mechanism (which operation's flush carried step 1's selection, and how that operation completed), not by the scenario's parameters.
- One sequence can be traced: `EXTEND_MODEL_TRACE='<its describe() line>' build/extend_completion_model_test` prints every step.

## Limits

- The model's timing is in LOK steps, not milliseconds: "the readback fires before the key ran" is a lag, not a stall of 250 ms; the window expires only when the LOK FIFO is idle (L-C-late-K1 is named, not modelled). A snapshot landing between two callbacks of one flush needs the LOK thread to stall for a page round trip; the model allows it because ruling 3 names that coincidence.
- One line, no separators, no tables: MergeKey and the fence are out of this model (unchanged, `merge_key_undo_model_test.cpp`).
- Writer's caret after a plain arrow on a range is the model's choice (one unit from the point, mark cleared); the comparisons are self-consistent and item 2 does not depend on where that caret lands.
- Undo restores one unit and selects it; the inline format changes nothing; the select-range targets are fixed at RESET 2, START 1, END 3.

### Condition 33: typing and an inline format behind a pending key (reported, not ruled)

Two follow-ups added to the generator beside Backspace: `Type` = paste of one unit, synchronous, replaces the selection; `Bold` = `.uno:Bold` with a listener, synchronous, bolds the selected units (on a caret Writer only arms the insertion attribute, no change). Both run at the next event boundary, ahead of every queued key, exactly as `.uno:Delete` does; the page consults no snapshot for them. Writer's reference applies the move first. The model's rectangles do not change width with bold, so a format's flush carries only its RESULT; natively a bolder line may re-send the selection rectangles (F1 deduplicates on the payload string), which would make an inline format on a range a member of L-extend-prior-flush as the earlier operation -- not modelled, named here.

- v20's keys, typing: 45,776 runs, 5,474 divergent: 5,458 "typing behind the user's queued plain move", 16 "behind the earlier queued plain move". Mechanism (traced, `E=none U=Right … Type(lagReg2=0)`): the Right is answered by the readback with its key queued; the paste runs first, `x` lands at the old caret and the Right then steps over the next unit: engine `xabcd` with the caret after `a`, Writer `axbcd`. Not a deletion; the typed text lands one unit early.
- v20's keys, inline format: 45,776 runs, 3,868 divergent, all "inline format behind the user's queued plain move". Mechanism (traced, `E=uno:undo U=Left … Bold(lagReg2=0)`): undo restores `z` selected; the Left is queued; `.uno:Bold` runs first on the still-selected `z`: engine `z*abcd`, Writer collapses first and bolds nothing. A format applied to text the user had just deselected.
- All keys (the next spec's scope): typing 366,912 runs, 44,902 divergent (23,892 behind the user's queued extend, 20,954 behind the user's queued plain move, 28 and 28 behind the earlier queued extend/plain move); inline format 366,912 runs, 41,722 divergent (23,886 behind the user's queued extend, 17,796 behind the user's queued plain move, 28 and 12 behind the earlier one). Behind a queued extend the typed unit replaces nothing where Writer replaces the extension, or the format bolds nothing where Writer bolds it.
- Every divergence has a key queued at the dispatch; none occurs with the FIFO empty. A select-range completed early with END still to run contributes under "behind … queued" only when a key is queued; with none queued the paste/format waits for nothing and matches Writer.
