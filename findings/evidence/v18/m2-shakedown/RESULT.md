## Correction, 2026-10-08 (after the finding 117 diagnosis): the `exit=0` lines in `chain.log` are not exit codes

`chain.sh` writes `echo "$(ts) END   $name exit=$?"`. Bash expands `$?` after the `$(ts)` command substitution, so the line records the substitution's status and always says 0 (measured: `bash -c 'false; echo "$(date +%s) exit=$?"'` prints `exit=0`; found in `../finding-118/attempt1/`, where runs that exited 3 were logged `exit=0`). So the sentence above, "every step `exit=0`", has no evidence behind its exit-code half. What still holds: every stderr file is empty (no traceback), and every report has `completedAt`. The merge runner's `main()` returns 0 unless it raises, so the steps very likely exited 0, but that is inference, not a record. Later chains save `rc=$?` first.
