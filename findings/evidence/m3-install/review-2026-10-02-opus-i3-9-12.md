## DETAILS

### 1. HEAVY — the orchestrator is on the runners' path as launcher and judge; window plan shape is never compared with dev
- **Claim.** §3.3 (:132) and I3-11 (:397-400) justify the single exception by "it is not on the runners' path": it is outside the runners' AST import closure and the Makefile doesn't name it. That checks runners→orchestrator only. In the window the orchestrator builds the runners' argv (`run_runner` :1014-1031; `extra = [] if counted else [...]` :1082). It also re-scores every runner and dev report in its own process (`runner_verdict` :1153). I3-12 (:1364-1372) compares only `criteria`. Assets, versions and locks pin their plan in their own strict score (PLAN counts). Host entry does not: `check_m3_host_entry.score` (:481-520) requires repeats == 3, both browsers, and broken arms in Chrome, but never `open-save` or `conflict`.
- **Evidence.**
  - In process, on the 09-29 dev host-entry report: dropping `conflict` from both browsers gives `lands True []`. Keeping only open-save plus Chrome's broken arms also gives `lands True []`.
  - On the synthetic window, with the real re-run `equivalence.json` and release commit 7420418, dropping `conflict` from the window host-entry report adds problems `[]` (I3-1..I3-12 all quiet).
  - The diff of `run_runner`..`load_reports` between `0972b6b2` and the working tree is empty, so this is not exercised.
  - The I3-7 report and the dev baseline both have Chrome {broken, broken-no-save, conflict, open-save} and Firefox {conflict, open-save}.
- **Failure scenario.** A future orchestrator fix, committed before an equivalence re-run, makes the counted path pass `--arms` (or a host-entry default changes in a way the orchestrator overrides). litecoreprobe then LANDS without H3, while the dev baseline's LANDS included H3. All of I3-8..I3-12 stay green. The hand-launched I3-7 run has the same gap (pre-existing).
- **Fix (form 1, per instance; does not touch owner decision B).** Extend I3-12 to "same inputs and plan": for each runner, the window report's plan shape must equal each judged dev report's. Shape means a Counter of (browser, arm) over `runs` for assets, versions and locks, and `{browser: {arm: len(runs)}}` plus `repeats` for host entry. Apply the same comparison to the I3-7 report. Fold item 4's `original` into this clause. Rewrite the self-proof sentence to say the orchestrator is the launcher and judge, and that this clause is what binds what it launches.
