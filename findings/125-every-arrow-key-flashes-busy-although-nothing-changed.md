# 125 — 每按一次方向鍵，狀態膠囊就閃一次「處理中」，而文件根本沒變

| | |
|---|---|
| **狀態** | 已確認、未修 |
| **所在** | 我們的頁面 `wasm_sdk_probe/web/e2-editor-app.js`：`updateState`（:614–619）把 session 的 `busy` 直接寫成膠囊的「處理中」；每一個引擎指令（包括移動游標）都會經過 `busy` |
| **發現日** | 2026-10-10（擁有者手測宿主 0.2.11） |
| **嚴重度** | 小：不影響資料，但每一鍵都閃黃色的「處理中」，讓人以為文件正在被改或存 |
| **可重現** | 每次（兩個瀏覽器，40 下方向鍵 40 次閃爍，每次 34–62 ms；打字也是每字一次） |
| **是否上游** | 否 |

## 現象

擁有者原話：「使用方向鍵移動游標，『處理中』就會一直閃爍，但內容明明沒有變更」。

## 重現步驟

1. 開任何文件、放游標。
2. 按方向鍵。

**預期**：只移動游標時，狀態不必說「處理中」。
**實際**：每一下都由「就緒」閃成「處理中」再回來（顏色也跟著變）。

## 證據

- `evidence/124/README.md`（與 124 同一支探針、同一次執行）。
- `evidence/124/arrows-{chrome,firefox}-1400x1000.json`：40 下方向鍵各 40 次閃爍，中位數 35.0／41.3 ms，修訂號全程不變；對照組 5 個字各 5 次閃爍、修訂號 +5——膠囊報的是「引擎在執行指令」，不是「文件在變」。

## 分析

- 「處理中」本身不假：引擎在那 35 ms 裡確實在處理指令。問題是它對使用者沒有資訊量，而且顏色閃動像是警示。
- Collabora 沒有逐指令的忙碌提示；它的忙碌視窗只給呼叫端點名的長動作（存檔、下載、上傳、重新連線），而且請求後 700 ms 才出現，在那之前結束就不出現（`cool-26-04/browser/src/control/Control.UIManager.ts` :644–689）。
- **限制條件**：膠囊的顏色由 `e2-editor.html` 裡的 CSS 依 `data-state` 決定（:28–33，那個檔案在雜湊網外，finding 094），而**每一支 runner 判斷狀態都讀膠囊的 `data-state`**（`run_e2_c_page_smoke.READ_STATE`）。所以「延後顯示」若做在 `data-state` 上，等於改了所有 runner 的狀態來源；做法要另外選（擁有者決定）。
- 不是 0.2.11 的退步。
