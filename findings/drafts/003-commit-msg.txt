tdf#NNNNNN gbuild: fix UnpackedTarball .version race with .dir under -j

On a fresh build directory, "make -j12" intermittently failed with

> /bin/sh: 1: cannot create .../workdir_for_build/UnpackedTarball/dragonbox.version:
> Directory nonexistent

Of three related targets in UnpackedTarball.mk, only two carry the
order-only prerequisite that creates the containing directory:

  $(call gb_UnpackedTarball_get_preparation_target,$(1)) :| $(dir ...).dir
  $(call gb_UnpackedTarball_get_target,$(1))             :| $(dir ...).dir

The .version target has none.  Since .prepare lists .version among its
normal prerequisites, and GNU make guarantees no ordering between a
target's normal and order-only prerequisites, under -j the recipe for
.version can run before .prepare's .dir prerequisite has been made.  The
directory does not exist yet and the shell redirection fails.

This usually goes unnoticed because UnpackedTarball/ has typically been
created by some other target already; only the first make in a fresh
build directory exposes it.  Observed on 2 out of 4 fresh build
directories on the same machine with -j12.

Give the .version target the same order-only prerequisite the other two
already have.
