Reply for the comment thread on configure.ac in https://gerrit.libreoffice.org/c/core/+/211916, as an answer to Chris Mayo's comment of 2026-11-17 19:26 UTC ("That's not something new caused by this MR is it?"), which is the last one in that thread. The fix was pushed as change 214345 on 2026-11-18; the number is filled in below.
================================================================

It is new with this change, at least for Emscripten: with `--with-distro=LibreOfficeWASM32`, configure passes on its parent 8e543468540d (`VCLplugs to be built: qt5`) and fails on d98a796946ff (`VCLplugs to be built: gtk3 qt5`, then `Can't build --disable-dynamic-loading without --disable-gui and a single VCL plugin`). `using_x11=yes` was there before, but for Emscripten `enable_wasm_strip` sets `with_x=no`, which cleared `USING_X11`, and `disable_x11_tests` then also turned off the gtk3, gtk4, kf5, kf6 etc. tests. Those tests now follow `using_unix_desktop`, and nothing clears `USING_UNIX_DESKTOP` for Emscripten.

I have pushed https://gerrit.libreoffice.org/c/core/+/214345 for it. Instead of setting `test_gtk*` in the platform block, as Christian suggested, it clears `USING_UNIX_DESKTOP` for Emscripten, next to where `with_x=no` clears `USING_X11`. I built both variants. With only `test_gtk3=no` in the platform block, configure passes and the build completes and starts too, so that would work as a fix. But `USING_UNIX_DESKTOP` stays `TRUE`, and compared to a WASM build from before this change the result then has `HAVE_FEATURE_OPENGL`, `ENABLE_OPENGL_TRANSITIONS` and `ENABLE_OPENGL_CANVAS` set, the desktop detector in `vcl`, the `s*` launcher scripts and `psprint` files in `instdir`, and about 700 more lines in `main.xcd`: the Unix desktop settings for `Inet`, `Paths`, `UserProfile` and `Common` (many of them to be read from the `DesktopBackend`) and the `unxwnt` accelerators. For example, F11 in Writer then opens the Styles deck, which it did not do before. With `USING_UNIX_DESKTOP` cleared, `config_host.mk` and `config_host/*.h` come out the same as before, apart from the new variable itself, and F11 does nothing, as before.

So I went for the variant that does not change what a WASM build contains. If you prefer the explicit `test_gtk*` in the platform block, or think WASM should get those settings, I can change it.
