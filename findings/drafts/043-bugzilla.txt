Description
-----------

After dispatching .uno:SelectText, the documented LOK sequence

    setTextSelection(LOK_SETTEXTSELECTION_RESET, x1, y)
    setTextSelection(LOK_SETTEXTSELECTION_END,   x2, y)

creates no selection at all.  There is no error: the call returns, the cursor
moves, getTextSelection() returns an empty string, and -- importantly for
callers that wait on it -- LOK_CALLBACK_TEXT_SELECTION is never broadcast,
because the selection genuinely did not change.

This is not a misuse of the API.  That exact two-call sequence is what
LibreOffice's own tiled-rendering test asserts:

    sw/qa/extras/tiledrendering/tiledrendering.cxx:151, in testSetTextSelection
      // Next: test that LOK_SETTEXTSELECTION_RESET + LOK_SETTEXTSELECTION_END
      // can be used to create a selection.
      pXTextDocument->setTextSelection(LOK_SETTEXTSELECTION_RESET, aStart.getX(), aStart.getY());
      pXTextDocument->setTextSelection(LOK_SETTEXTSELECTION_END, aStart.getX() + 1000, aStart.getY());
      CPPUNIT_ASSERT_EQUAL(u"Aaa b"_ustr, pShellCursor->GetText());

The existing test only covers the clean case.  Dispatching .uno:SelectText
first makes the same two calls fail.


Steps to reproduce (LOK API level)
-----------------------------------

1. documentLoad() a Writer document, initializeForRendering(), paint a tile so
   the layout exists.
2. setTextSelection(RESET, x, y) to place a collapsed cursor in a paragraph.
3. postUnoCommand(".uno:SelectText", nullptr, true)   -- selects the paragraph.
4. setTextSelection(RESET, x, y)                      -- collapse it again.
5. setTextSelection(RESET, x1, y)
   setTextSelection(END,   x2, y)                     -- ask for a range.
6. getTextSelection("text/plain;charset=utf-8")

Expected: the text between x1 and x2.
Actual:   empty string, getSelectionType() == LOK_SELTYPE_NONE, and no
          LOK_CALLBACK_TEXT_SELECTION was broadcast for step 5.

Notes:
  * Step 3 is the only thing that matters.  Without it, step 5 works.
  * No format command is involved.  We first met this after .uno:DefaultBullet,
    but a run with the format command and WITHOUT .uno:SelectText selects fine,
    and a run with .uno:SelectText and NO format command fails.
  * Repeating step 5 a second time, with nothing dispatched in between,
    SUCCEEDS.  See "Mechanism" -- the failed attempt clears the state itself.


Proposed regression test (ready to paste)
------------------------------------------

Modelled on the existing testSetTextSelection in the same file:

    CPPUNIT_TEST_FIXTURE(SwTiledRenderingTest, testSetTextSelectionAfterSelectPara)
    {
        SwXTextDocument* pXTextDocument = createDoc("dummy.fodt");
        SwWrtShell* pWrtShell = getSwDocShell()->GetWrtShell();
        pWrtShell->Right(SwCursorSkipMode::Chars, /*bSelect=*/false, 5, /*bBasicCall=*/false);
        pWrtShell->SelWrd();
        SwShellCursor* pShellCursor = pWrtShell->getShellCursor(false);
        Point aStart = pShellCursor->GetSttPos();

        // Select the paragraph the way .uno:SelectText does, then collapse.
        comphelper::dispatchCommand(u".uno:SelectText"_ustr, {});
        Scheduler::ProcessEventsToIdle();
        pXTextDocument->setTextSelection(LOK_SETTEXTSELECTION_RESET, aStart.getX(), aStart.getY());

        // Exactly the sequence testSetTextSelection already asserts works.
        pXTextDocument->setTextSelection(LOK_SETTEXTSELECTION_RESET, aStart.getX(), aStart.getY());
        pXTextDocument->setTextSelection(LOK_SETTEXTSELECTION_END, aStart.getX() + 1000, aStart.getY());
        CPPUNIT_ASSERT(!pShellCursor->GetText().isEmpty());   // fails before the fix
    }


Mechanism -- NOT VERIFIED, treat as a hypothesis
-------------------------------------------------

The report above stands without this section; delete it and the reproducer is
unchanged.  We never read the flag named below -- SwWrtShell::IsInSelect() is
in sw/source/uibase/inc/wrtsh.hxx:154 and is not reachable from an external LOK
probe -- so this is a source reading plus its externally observable
consequences, not a measurement of the flag itself.

  1. sw/sdi/swriter.sdi:5649           .uno:SelectText -> FN_SELECT_PARA
  2. sw/source/uibase/shells/textsh1.cxx:1975
                                        FN_SELECT_PARA ends in EndPara(true)
  3. sw/source/uibase/wrtsh/move.cxx:402
                                        EndPara(true) -> ShellMoveCursor(this, true)
                                        -> MoveCursor(true)
  4. sw/source/uibase/wrtsh/move.cxx:84 MoveCursor(true) calls SttSelect()
  5. sw/source/uibase/wrtsh/select.cxx:421
                                        SttSelect() sets m_bInSelect = true

     Nothing on that path calls EndSelect().  ShellMoveCursor's destructor
     (move.cxx:62-71) only does StartAllAction/EndAllAction.

  6. sw/source/uibase/docvw/edtwin.cxx:7105
                                        A later setTextSelection(RESET) takes
                                        the bClearMark branch: ClearMark() only,
                                        bCreateSelection stays false, so neither
                                        SttSelect() nor EndSelect() runs and the
                                        flag survives.
  7. sw/source/uibase/docvw/edtwin.cxx:7107-7111
                                        The caller's END has HasMark() == false,
                                        so bCreateSelection = true and it calls
                                        SttSelect().
  8. sw/source/uibase/wrtsh/select.cxx:409
                                        `if (m_bInSelect) return;` -- early
                                        return, SetMark() never runs.

No mark, no selection.  Step 7's SetCursor() just moves the cursor.

Why the second attempt succeeds: EndSelect() at edtwin.cxx:7121-7122 is called
on bCreateSelection, not on whether SttSelect() did anything, so the failed
attempt clears the flag on its way out.

For contrast, search in the same tree DOES pair them:
sw/source/uibase/uiview/viewsrch.cxx:773 SttSelect() with :846 EndSelect().

Suggested fixes (not verified by us)
-------------------------------------

1. Give FN_SELECT_PARA a matching EndSelect(), the way viewsrch.cxx does.
   Smallest, and consistent with the existing convention in the tree.

2. Make SwWrtShell::SttSelect()'s early return not skip the mark -- move
   `if (!HasMark()) SetMark();` above `if (m_bInSelect) return;`.  Wider blast
   radius than (1), but it fixes the more general shape: a caller believes it
   opened a selection and it did not.

3. Either way, add the regression test above.  The existing
   testSetTextSelection only covers the clean state.
